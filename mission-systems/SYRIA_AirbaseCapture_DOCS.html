SYRIA AirbaseCapture

SYRIA_AirbaseCapture.lua  ·  Dynamic ownership & F10 map drawing  ·  Syria map  ·  Standalone — no dependencies

How It Works

Three things happen, in this order:

  1. Script loads — reads ABC.REGISTRY and ABC.DESTROY_REGISTRY, runs a quick unit scan to correct any bases that start without defenders, then draws a coloured circle on the F10 map for every entry using the matching CAPTURE_ZONE_* / DESTROY_ZONE_* trigger zone in the ME for exact position and radius.
  2. Every 180 seconds — counts ground units of each coalition inside each zone. Capture bases: accumulate ticks when one side has units and the other doesn't, flip after 3 consecutive ticks. Destroy zones: permanently flip to black when RED unit count reaches zero.
  3. On flip — recolours the circle, announces to all players, fires the optional ABC.onCapture callback (capture zones only).
You provide: Trigger zones in the ME — one CAPTURE_ZONE_* per base and one DESTROY_ZONE_* per target set. The script provides: everything else — circles, scanning, state tracking, announcements. No MIST required.

Configuration — Timing

Click any row to expand the full explanation.

CHECK_INTERVAL 180 s How often the script scans all zones for units. ▼ details

Every CHECK_INTERVAL seconds the main scanAll() loop fires and checks every registered base. It counts ground units of each coalition inside the trigger zone, increments capture ticks if appropriate, and redraws labels if anything changed.

Practical effect: This is the "heartbeat" of the entire system. Lowering it makes the game feel more real-time (units react quickly), raising it makes captures slower and less sensitive to brief incursions. At 180 s with 3 ticks, the minimum capture time is 9 minutes of uncontested presence.

Tuning guide:
• Fast / arcade: 30 s → min capture 1.5 min
• Balanced: 60 s → min capture 3 min
• Slow / milsim: 180 s → min capture 9 min (current)
• Very slow: 300 s → min capture 15 min

CAPTURE_TICKS 3 How many consecutive successful scans are needed to flip a base. ▼ details

A "tick" is one successful scan where the capturing side has units present and the defending side has none. CAPTURE_TICKS defines how many of those in a row are needed before ownership actually changes.

Why it exists: Without this, a single scout vehicle driving through would flip a base. The tick system requires sustained, uncontested occupation.

Ticks reset to 0 if the defending side returns before the threshold is reached. A partially-captured base (e.g. 2 of 3 ticks done) goes back to 0 if contested.

The F10 label shows a "Capturing... X%" progress during the tick accumulation so players can see it happening in real time.

Minimum capture time = CHECK_INTERVAL × CAPTURE_TICKS. At defaults: 180 × 3 = 540 s = 9 min.

MIN_CAPTURE_UNITS 1 Minimum friendly ground units needed inside the zone to start a tick. ▼ details

The capturing side must have at least this many live ground units inside the trigger zone when the scan fires. If their count is below the threshold, no tick is awarded even if the enemy is absent.

Default of 1 means a single infantry unit is enough to contest a base. Raise to 3 or 5 to require a meaningful force rather than a lone scout.

Note: This threshold applies independently to each side. If RED has 5 and BLUE has 0, RED accumulates. If BLUE has 1 and RED has 5, the base is contested — neither ticks up.

Configuration — Scanning

SCAN_AIR false Whether aircraft and helicopters count toward zone presence. ▼ details

When false (default), only ground units (Group.Category.GROUND) are counted. This is the realistic default — a jet flying over a base doesn't "occupy" it.

When true, the script also counts AIRPLANE and HELICOPTER categories. This means a helicopter hovering over a zone contributes to capture ticks. Useful for FARP capture scenarios where heliborne assault is the primary mechanic.

Performance note: Setting this to true roughly doubles the unit iteration cost per scan since all air units in both coalitions are also checked. On large missions this is negligible; on missions with hundreds of aircraft it adds a small overhead every CHECK_INTERVAL seconds.

Configuration — Map Drawing

CIRCLE_RADIUS 6500 m (fallback only) Fallback radius used only when no matching trigger zone is found in the ME. ▼ details

Normally this value is never used. The script reads the radius directly from the trigger zone you placed in the ME (trigger.misc.getZone(entry.zone).radius), so the drawn circle always exactly matches your ME zone. CIRCLE_RADIUS is only the fallback when a zone name is missing from the ME.

To change the visual size of a circle, resize the trigger zone in the ME — not this config value.

COLOR_* / FILL_* {r, g, b, a} RGBA colour arrays for each state's ring outline and fill. ▼ details

Eight entries total — an outline (COLOR_*) and fill (FILL_*) pair for each of the four states: RED, BLUE, NEUTRAL, DESTROYED. All use DCS positional array format {r, g, b, a} where values are 0–1.

Important: DCS requires positional arrays (numeric indices). Named keys like {r=1, g=0, b=0, a=1} are silently ignored and produce invisible marks. Always use {1.0, 0.0, 0.0, 1.0} format.

Ring outlines use a=1.0 for full opacity. Fill colours use a=0.15 to keep the interior diffuse without obscuring the map terrain.

LINE_TYPE 1 (Solid) Border line style: 1=Solid, 2=Dashed, 3=Dotted, 4=Dot-Dash. ▼ details

DCS supports four line types for circleToAll. The default solid line (1) gives the clearest visibility. Dashed (2) or dotted (3) can help if you have many overlapping zones and want to distinguish them.

LABEL_FONT_SIZE 14 Point size of the base name + status text on the F10 map. ▼ details

Controls the size of the text label drawn next to each circle. The label shows the base name on line 1 and the ownership status on line 2 (e.g. [ RED ]). During active capture it adds a third line showing percentage progress.

DCS renders F10 map text at fixed pixel sizes regardless of zoom level, so larger values are easier to read when zoomed out at the strategic level. Reduce to 10–11 if labels feel cluttered.

Configuration — Mark IDs

BASE_MARK_OFFSET 6000 Starting integer ID block for all capture zone F10 marks. ▼ details

Each capture base reserves MARKS_PER_BASE (3) consecutive IDs starting at BASE_MARK_OFFSET + (index × 3). With 22 registry entries, IDs 6003–6069 are used. Slot 0 = circleToAll, slot 1 = textToAll, slot 2 = spare.

Change this value if another script in your mission uses overlapping mark IDs. A collision causes one script to silently delete the other's marks every redraw.

DESTROY_MARK_OFFSET 7000 Separate starting ID block for all DESTROY_ZONE_* F10 marks. ▼ details

Destroy zone marks use a completely separate ID range starting at 7000 so they never conflict with capture zone marks. The same 3-slot-per-entry layout applies. With the defaults, IDs 7003–7999 are available — enough for up to 333 destroy zones.

Increase if you have another script using IDs in that range.

MARKS_PER_BASE 3 How many mark IDs are reserved per entry (circle + label + 1 spare). ▼ details

Currently 2 marks are used per entry (circle at slot 0, text label at slot 1). Slot 2 is reserved for future expansion. Do not reduce this below 2. This setting applies to both BASE_MARK_OFFSET and DESTROY_MARK_OFFSET blocks.

Function — ABC.getOwner()

ABC.getOwner(baseName)→ "RED" | "BLUE" | "NEUTRAL" | "DESTROYED" | nil
Query who currently owns a capture base.
▼ details

Returns the current coalition string for the named base. Returns nil if the name is not in the registry. Name is case-sensitive and must match the name field in ABC.REGISTRY exactly.

-- Spawn a convoy only if Aleppo is BLUE-held
if ABC.getOwner("Aleppo") == "BLUE" then
  GROUP_Convoy:activate()
end

-- Count RED-held bases
local n = 0
for _, name in ipairs({"Mezzeh","Hama","Palmyra","Tabqa"}) do
  if ABC.getOwner(name) == "RED" then n = n + 1 end
end

Function — ABC.setOwner()

ABC.setOwner(baseName, coalition)
Force a base to a specific coalition instantly, bypassing capture ticks. Announces and redraws.
▼ details

Immediately assigns the given coalition ("RED", "BLUE", or "NEUTRAL") to the base, redraws the F10 circle, broadcasts an [AIRBASE CAPTURE] message to all players, and fires the optional ABC.onCapture callback.

This is the preferred function for scripted ownership changes from DO SCRIPT triggers. It replaces the older forceCoalition() which does the same thing but with a less clear name.

-- Blue secured Palmyra via a mission objective
ABC.setOwner("Palmyra",  "BLUE")

-- Reset Tabqa after a RED counter-attack
ABC.setOwner("Tabqa",    "RED")

-- Contested — neither side holds it anymore
ABC.setOwner("At Tanf",  "NEUTRAL")

Function — ABC.forceCoalition()

ABC.forceCoalition(baseName, coalStr)
Identical to setOwner() — retained for backwards compatibility.
▼ details

Calls the same internal applyCoalition() function as setOwner(). Prefer setOwner() for new scripts; use forceCoalition() only if you have existing triggers already calling it.

ABC.forceCoalition("Hama", "BLUE")   -- same as ABC.setOwner("Hama","BLUE")

Function — ABC.setDestroyed()

ABC.setDestroyed(baseName)
Mark a capture base as permanently destroyed. Black circle, yellow "Destroyed" label.
▼ details

Sets the base state to "DESTROYED" — a terminal state. The scan loop skips destroyed bases entirely. The F10 circle recolours to a black ring with black fill, and the label changes to the base name + "Destroyed" in yellow text. A [AIRBASE DESTROYED] message is sent to all players.

DESTROYED is final for the mission unless you explicitly call ABC.setOwner() or ABC.forceCoalition() to override it.

This function operates on ABC.REGISTRY entries (capture bases). Destroy zone entries in ABC.DESTROY_REGISTRY transition to DESTROYED automatically when their zone empties — they don't use this function.

-- From a DO SCRIPT trigger when runway objects are confirmed dead
ABC.setDestroyed("Shayrat")

Function — ABC.registerFARP()

ABC.registerFARP(farpName, zoneName, startCoal, pos)
Add a FARP to the capture system at runtime with an explicit world position.
▼ details

Use for FARPs that don't have a DCS Airbase object and whose position isn't known at script load time. Adds the FARP as a new registry entry, allocates mark IDs, draws it on the F10 map immediately, and includes it in all future scans.

ParamTypeDescription
farpNamestringUnique name — also the key used for all API calls
zoneNamestringExact name of a CAPTURE_ZONE_* trigger zone placed in the ME
startCoalstring"RED", "BLUE", or "NEUTRAL"
posVec3World coordinates — from Airbase.getByName(name):getPoint() or a static object
-- Delayed trigger at T+5s (FARP object must exist by then)
ABC.registerFARP(
  "FARP_Khanasir",
  "CAPTURE_ZONE_FARP_Khanasir",
  "RED",
  Airbase.getByName("FARP_Khanasir"):getPoint()
)

Safe to call for an already-registered name — logs a warning and returns without duplicating it.

Function — ABC.redrawAll()

ABC.redrawAll()
Delete and redraw every F10 map circle from scratch.
▼ details

Iterates every entry in ABC.REGISTRY, removes all existing marks, and redraws fresh circles in the current coalition colour. Useful if marks have been accidentally deleted (e.g. another script with conflicting mark IDs) or after a batch of ownership changes.

Note: Does not redraw destroy zone entries in ABC.DESTROY_REGISTRY. Those use a separate state table and are redrawn automatically by the scan loop when they change state.

Cost: ~2 DCS API calls per registered base. On a typical Syria setup with 22 entries this is ~44 calls — fine as a one-off call, but do not call it in a tight loop.

Callback — ABC.onCapture

ABC.onCapture = function(baseName, prevCoal, newCoal) ... end
Optional hook called on every capture zone ownership change.
▼ details

If you assign a function here it is called (via pcall) every time a capture zone changes ownership — whether via normal ticks, setOwner, forceCoalition, or setDestroyed. A crash inside your callback will not break the capture loop.

Does not fire for destroy zone transitions — those are independent of the capture system.

ParameterTypeValue
baseNamestringName of the base that changed
prevCoalstringPrevious coalition
newCoalstringNew coalition after the change
-- Set in a DO SCRIPT trigger 1–2 seconds after the DO SCRIPT FILE load
ABC.onCapture = function(base, from, to)
  -- Trigger immediate IADS rebuild when a base changes hands
  if type(buildNodeList) == "function" then
    buildNodeList(coalition.side.RED)
    buildNodeList(coalition.side.BLUE)
  end
  -- Award points
  if to == "BLUE" then
    missionScore = (missionScore or 0) + 100
  end
end

Only one callback at a time — assigning again overwrites the previous value. Set it in a separate DO SCRIPT trigger at T+1 s so it's assigned after ABC.init() has finished.

Destroy Zone Registry (ABC.DESTROY_REGISTRY)

A separate list for RED target sets — SAM sites, command posts, fuel depots — that players are tasked with neutralising. These zones are never capturable. Once the RED units inside are destroyed, the zone is permanently black.

Behaviour

  • Draws a red circle on the F10 map at mission start (same colour as RED airbases).
  • Every CHECK_INTERVAL seconds the script counts live RED units inside the zone.
  • When the count reaches zero the circle permanently turns black, the label gains a yellow "Destroyed" sub-line, and a [TARGET DESTROYED] message is broadcast to all players.
  • A zone that already has no RED units at mission start immediately draws as DESTROYED.

Adding a Destroy Zone

  1. Place your RED unit group in the ME.
  2. Draw a circle trigger zone over all the units. Name it DESTROY_ZONE_<YourName>. Set the radius to cover all units in the group.
  3. Add an entry to ABC.DESTROY_REGISTRY: 
    { name = "SA-10 North",  zone = "DESTROY_ZONE_SA10_NORTH" },

Entry Fields

FieldDescription
nameDisplay name shown on the F10 map label
zoneExact DESTROY_ZONE_* trigger zone name in ME
Zone sizing matters. A unit standing 1 m outside the zone radius is not counted. Make the zone radius comfortably larger than the unit spacing. The drawn circle on the F10 map will match the zone exactly, so a zone that's too small will produce a circle that doesn't visually cover the units.

Mission Editor Setup Checklist

  1. Load script — MISSION START trigger → DO SCRIPT FILE: SYRIA_AirbaseCapture.lua. No MIST required.
  2. Capture zones — place one trigger zone per capturable base, named exactly as the zone field in the registry (e.g. CAPTURE_ZONE_PALMYRA). Zone radius in ME sets the drawn circle size and the unit-scan area — recommended 6–10 km for airbases, 2–4 km for FARPs.
  3. Destroy zones — place one trigger zone per RED target set, named DESTROY_ZONE_<Name>. Add a matching entry to ABC.DESTROY_REGISTRY. Zone radius should cover all units in the group.
  4. FARPs — add a delayed DO SCRIPT trigger (T+5 s) calling ABC.registerFARP(...) for any FARP placed in the ME at runtime.
  5. Callback — if using ABC.onCapture, assign it in a separate DO SCRIPT trigger at T+1 s (not in the same trigger as DO SCRIPT FILE).
  6. Ownership overrides — use DO SCRIPT triggers calling ABC.setOwner(name, coal) to pre-set any ownership state before or during the mission.
Quick test: load the mission and open the F10 map. You should see coloured circles immediately on mission start — red for RED airbases, white/grey for NEUTRAL FOBs, and red for destroy zones. Circles match the position and size of your ME trigger zones exactly.
