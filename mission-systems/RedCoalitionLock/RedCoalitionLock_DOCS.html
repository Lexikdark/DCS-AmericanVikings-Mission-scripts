RedCoalitionLock

v1.0 Multiplayer Only No Dependencies Prevents players from occupying Red coalition slots · AI and dynamic spawns unaffected

Overview

A lightweight enforcement script that locks the Red coalition to AI-only. Because DCS does not provide a native in-mission option to block a coalition from player use while still allowing dynamic spawn / airbase capture mechanics, this script fills that gap by scanning all connected players every 5 seconds and immediately ejecting anyone found on the Red side back to Spectators.

Why this is needed: When Red airbases have Dynamic Spawn enabled (so Blue players can capture them), DCS also makes those slots available to Red-side human players. This script ensures that can never happen without disabling Dynamic Spawn or altering airbase settings.
Safe by design — uses only net.force_player_slot() and net.send_chat_to(). No Red AI, no groups, no triggers, no airbase settings and no other scripts are touched in any way.

Configuration

Three constants at the top of the file can be adjusted:

RED_COALITION
1
DCS internal coalition ID for Red. Do not change unless DCS changes this value.
CHECK_INTERVAL
5 seconds
How often the enforcement scan runs. Lower values give a tighter lock; higher values reduce server overhead. 5 s is a good balance.
KICK_MESSAGE
"[SERVER] Red coalition is reserved for AI only..."
The private chat message sent to the player when they are ejected. Edit this string to customise the message shown.

Enforcement Logic

The script runs a single self-rescheduling timer function — enforceRedLock() — every CHECK_INTERVAL seconds. On each tick it:

  • Calls net.get_player_list() to get the IDs of all currently connected players.
  • Skips player ID 1 — this is always the server/host process, never a human player.
  • For each remaining player, calls net.get_player_info(pid) and checks the side field.
  • If side == 1 (Red), calls net.force_player_slot(pid, 0, "") to move them to Spectators.
  • Sends the player a private chat message explaining why they were moved.
  • Logs the action to dcs.log with the player name and slot they were removed from.
There is an inherent window of up to 5 seconds during which a player could technically occupy a Red slot before being ejected. This is unavoidable with a polling approach but is not exploitable in any meaningful way — the slot is cleared before they can do anything significant.

Enforcement Flow

1
Script loads at Mission Start

Schedules first enforcement check 10 seconds after load, giving DCS time to fully initialise multiplayer state.

2
Check for net library

If net is not present (single-player / ME preview), the function exits immediately and reschedules itself. No errors, no side effects.

3
Scan all connected players

Iterates the player list returned by net.get_player_list(). Skips the server process (ID 1).

4
Check coalition side

Reads net.get_player_info(pid).side. Blue (side 2), Spectators (side 0), and unslotted players are ignored entirely.

5
Eject Red player → Spectators

net.force_player_slot(pid, 0, "") moves the player to Spectators. A private chat message is sent. The action is written to dcs.log.

6
Reschedule

Returns timer.getTime() + CHECK_INTERVAL to self-reschedule for the next tick. Runs indefinitely for the duration of the mission.

Mission Editor Checklist

  • Add a Mission Start trigger — Type: ONCE, Condition: Mission Start.
  • Add a DO SCRIPT FILE action to that trigger pointing to RedCoalitionLock.lua.
  • No load order requirement — this script has no dependencies. It can be the first or last script loaded.
  • No ME zones, groups, or units needed — the script is entirely self-contained.
  • Verify in dcs.log — on mission start you should see: [RedLock] RedCoalitionLock loaded. Red slots locked to AI only.

Troubleshooting

SymptomLikely CauseFix
Red players are not being ejected Running in single-player or ME preview where net is unavailable Test on a multiplayer server. The script silently does nothing in single-player by design.
No log entry on mission start Script file not loaded — DO SCRIPT FILE trigger may be misconfigured or pointing to wrong path Check the trigger action in ME. Ensure the file path is correct and the trigger fires on Mission Start.
Players ejected from Blue slots incorrectly Cannot happen — only side == 1 (Red) is acted on If seen, verify RED_COALITION = 1 has not been changed accidentally.
Player appears briefly in a Red aircraft before ejection Expected behaviour — polling has up to a 5-second window Reduce CHECK_INTERVAL to 2 for a tighter response at the cost of slightly more frequent net calls.
Script errors in dcs.log referencing net Unlikely — net presence is checked before any call is made If it occurs, verify the DCS version supports net.get_player_list() (available since DCS 2.7+).
