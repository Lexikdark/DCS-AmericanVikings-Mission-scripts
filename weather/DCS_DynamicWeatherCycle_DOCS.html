DCS_DynamicWeatherCycle.lua American Vikings Syria

Complete usage and editing guide for the dynamic weather cycle script — covering installation, every configurable value, how to edit the weather stages, and common customisation recipes.

Overview

DCS_DynamicWeatherCycle.lua is a mission script for the American Vikings Syria server that creates a realistic, repeating weather cycle — progressing from clear sunny skies through a building storm, a full thunderstorm, and back to clear over a 12-hour mission time loop.

It broadcasts live ATIS-style weather reports to pilots every 5 minutes, issues advance warnings before dangerous weather arrives, and reports wind trends (veering, backing, rising speed) in real time.

What the script does vs what DCS does The DCS scripting engine cannot change cloud presets, fog, or visibility at runtime — that is a hard engine limitation. The script handles everything else: ATIS broadcasts, stage warnings, wind trend reporting, and the timing cycle. The actual sky is evolved automatically by DCS's own dynamic atmosphere engine based on the starting conditions you set in the ME Weather tab.

How It Works

What the Lua Script does
  • Runs a state machine with 6 named weather stages
  • Polls atmosphere.getWind() at 3 altitudes every 30 seconds
  • Reads temperature and pressure via atmosphere.getTemperatureAndPressure()
  • Broadcasts ATIS reports every 5 minutes (or on demand)
  • Issues 30-minute advance warnings before each stage boundary
  • Announces when a new stage begins
  • Tracks wind speed trend and direction (veering / backing)
  • Resets the cycle automatically every 12 hours of mission time
What DCS does automatically
  • Gradually drifts wind direction over hours
  • Fluctuates wind speed around the ME starting value
  • Shifts barometric pressure as a weather system moves through
  • Varies turbulence around the baseline
  • All of this happens because atmosphere_type = 1 (Dynamic) is set
  • No extra triggers are needed — DCS handles it on its own

Scheduler Loop

The script uses timer.scheduleFunction() to create a self-rescheduling 30-second tick loop. Every tick it:

  1. Determines the current weather stage from elapsed mission time
  2. Checks whether a 30-minute stage warning needs to fire
  3. Checks whether a stage boundary has been crossed (and announces it)
  4. Checks whether 5 minutes have passed since the last ATIS broadcast
  5. Checks whether the manual ATIS User Flag has been set

Installation

1
Create one trigger in the Mission Editor
In the ME Triggers editor, add a trigger:
Type: ONCE
Condition: MISSION START
Action: DO SCRIPT FILE → browse to DCS_DynamicWeatherCycle.lua

This fires the script the instant the mission loads. That is the only trigger you need — no additional triggers are required.
2
Set up the Weather tab in the Mission Editor
Open the Mission Editor → Weather tab and configure:

• Atmosphere Type = Dynamic — this tells DCS to naturally evolve wind, pressure, and turbulence over time
• Starting cloud preset — pick whatever sky you want at mission start (e.g. Preset2 for sunny)
• Wind, temperature, pressure — set your baseline; DCS will drift from these values as the mission runs

DCS handles all the atmospheric evolution from here. No extra triggers needed.
3
(Optional) Set AIRFIELD_REF to your primary base
Open the script and update AIRFIELD_REF in the CFG block with the DCS world coordinates of your main operating airfield on Syria. This is the point used for ATIS sampling. See the Configuration section for Syria airfield coordinate values.
That is all Launch the mission. A startup message appears within 30 seconds and a full ATIS within 60 seconds. The script runs the entire cycle automatically from here.

Cycle Timeline

The script's broadcast text follows this 12-hour cycle, then resets automatically. The actual sky is driven by DCS's dynamic atmosphere, which will naturally trend through similar conditions based on your ME starting settings — wind building, pressure dropping during a storm, then recovering as it clears.

    T+07:00 → T+09:30
    🌦 CLEARING
    Storm passing. Broken stratocumulus, base rising to 3 900 ft. NW wind 15–22 kts with occasional gusts. Visibility 8–20 km, patchy fog lifting. Hazards: residual turbulence, wet runway.
  • MVFR
    T+09:30 → T+12:00
    ☁ OVERCAST
    Broken cumulus, base 5 900 ft. Northerly 8–14 kts, steady. Visibility 20–40 km. No significant hazards.

    ☀ CLEAR (cycle reset)
    Back to CAVOK. Few cumulus 7 200 ft. NNE light wind 4–8 kts. Script resets its internal clock and warning flags automatically.

Configuration — the CFG Block

All user-facing settings are collected in the CFG table near the top of the script. You only need to edit this section for most customisations. 

local CFG = {
    AIRFIELD_REF        = { x = -35000, y = 0, z = 75000 },
    ATIS_INTERVAL       = 300,
    WARN_LEAD_TIME      = 1800,
    ATIS_FLAG           = 10,
    WIND_HISTORY_SIZE   = 6,
    BROADCAST_COALITION = 2,
    MSG_DURATION_SHORT  = 12,
    MSG_DURATION_LONG   = 25,
}
KeyDefaultWhat it does
AIRFIELD_REF x=-35000, y=0, z=75000 DCS world coordinates of your primary airfield. This is where atmosphere.getWind() and atmosphere.getTemperatureAndPressure() are sampled. Get the coordinates from the F10 map (right-click → Coordinates, or use the Mission Editor unit placement and read X/Y from the status bar). y should always be 0 (ground altitude — DCS adds terrain height internally).
ATIS_INTERVAL 300 Seconds between automatic ATIS broadcasts. 300 = every 5 minutes. Increase to 600 for a 10-minute interval on busy servers.
WARN_LEAD_TIME 1800 Seconds before a stage transition that an advance warning is issued. 1800 = 30 minutes. Set to 600 for a 10-minute warning instead.
ATIS_FLAG 10 DCS User Flag number. When a trigger sets this flag to any value >0, an immediate ATIS broadcast fires. Useful for JTAC/GCI triggers or F10 radio menu "Request ATIS" options.
WIND_HISTORY_SIZE 6 Number of wind samples kept for trend analysis. Each sample is taken every 5 minutes (ATIS_INTERVAL). 6 samples = ~30 minutes of wind history. Increase for smoother trend reporting.
BROADCAST_COALITION 2 Who receives weather messages. 0 = everyone, 1 = Red coalition only, 2 = Blue coalition only.
MSG_DURATION_SHORT 12 Seconds a short notification stays on screen.
MSG_DURATION_LONG 25 Seconds a full ATIS or warning message stays on screen.

Editing Weather Stages

The WEATHER_STAGES table controls everything the Lua script announces (text content, hazards, flight category). Each stage is a Lua table with these fields:

FieldTypePurpose
startMin number Mission time in minutes when this stage's broadcast text becomes active. Only the script reads this — no ME trigger needed.
name string Shown in ATIS headers and transition announcements. Special logic checks for "THUNDERSTORM", "CLEARING", "OVERCAST", and "CLEAR" to pick the right warning tone.
category string Flight rules category shown in brackets: VFR, MVFR, IFR, or LIFR.
windDesc string Plain-English wind forecast shown in the ATIS WINDS line. Describes the expected wind character during this stage.
cloudDesc string Sky condition description shown in the ATIS SKY line. Should match what the ME cloud preset actually looks like.
visDesc string Visibility description shown in the ATIS VIS line.
hazards table of strings List of pilot NOTAMs shown at the bottom of each ATIS and transition message. Use an empty table {} for no hazards.

Example — adding a stage

To insert a new Dust Haze stage between CLEAR and BUILDING, add a new block and shift subsequent startMin values. No ME trigger needed — just edit the script. 

-- Insert this block after the first CLEAR stage
{
    startMin  = 90,   -- 1h30m into mission
    name      = "DUST HAZE",
    category  = "MVFR",
    windDesc  = "Easterly shamal wind 12-18 kts, gusting",
    cloudDesc = "Sky obscured by dust, base indeterminate",
    visDesc   = "4-8 km in blowing dust",
    hazards   = {
        "Reduced visibility — all aircraft file IFR",
        "Dust ingestion risk — avoid low-level hover",
    },

},

ATIS Broadcasts & User Flags

Automatic ATIS

A full weather report is broadcast automatically every 5 minutes (configurable via ATIS_INTERVAL). The first broadcast fires 30 seconds after mission start. The report format is: 

══ AMERICAN VIKINGS WEATHER – 04:32 ══
STATUS: BUILDING  [MVFR]

SURFACE  195° / 14 kts
2 000 m  200° / 18 kts
8 000 m  215° / 24 kts
TREND: speed RISING +4 kts | veering 9°

QNH: 1009 hPa  (29.80 inHg / 757 mmHg)
TEMP: +22°C

SKY: Scattered to broken, base lowering 2600 ft
VIS: 15-25 km, haze developing
WINDS: South-Southwesterly, increasing 10-18 kts, veering

NOTAM:
  ⚠ Cloud base lowering
  ⚠ Wind shift imminent

On-Demand ATIS via User Flag

Any ME trigger can request an immediate ATIS broadcast by setting User Flag 10 (or whichever number is set in CFG.ATIS_FLAG) to a value greater than 0. The script resets the flag to 0 after broadcasting, so it can be triggered again.

Typical use cases:

  • Add an F10 radio menu option "Request ATIS" → SET USER FLAG 10 = 1
  • Trigger an ATIS at a specific mission moment (e.g. on game start, or after a phase change)
  • A JTAC or GCI unit can trigger it with a proximity / communication trigger
-- ME trigger action equivalent:
-- Condition: any (e.g. FLAG IS TRUE, or RADIO MENU)
-- Action: SET USER FLAG → Flag: 10, Value: 1

Transition Warnings

30 minutes before each stage boundary the script broadcasts a single advance warning. It fires only once per stage (a guard flag prevents repeats). The warning tone differs by stage:

  • → THUNDERSTORM: Full red weather warning with evacuation advisory
  • → CLEARING / OVERCAST / CLEAR: Informational "conditions improving" update
  • All other transitions: Generic trend notice

Function Reference

These are the internal functions in the script, in case you want to extend or debug it.

broadcastATIS ( missionTimeSec )

Samples atmosphere.getWind() at surface, 2 000 m, and 8 000 m. Samples temperature and pressure. Builds and broadcasts the full ATIS text block. Records the surface wind sample for trend calculation. Updates State.lastAtisTime.

weatherTick ( _, time )

The main loop function. Called by timer.scheduleFunction() and returns time + 30 to reschedule itself 30 seconds later. Calls getCurrentStage(), checkTransitionWarnings(), checkStageTransition(), and either broadcastATIS() or checkManualATISFlag().

getCurrentStage ( missionTimeSec )

Iterates WEATHER_STAGES in reverse to find the last stage whose startMin has been passed. Sets State.currentStageIndex and returns the stage table. Safe to call repeatedly — has no side effects other than updating the index.

checkTransitionWarnings ( missionTimeSec )

For each stage, checks whether we are within WARN_LEAD_TIME seconds of its startMin. If so, fires a warning once (guarded by State.warningsFired[i]). On cycle reset, warningsFired is cleared so warnings fire again in the next cycle.

checkStageTransition ( missionTimeSec )

Compares State.currentStageIndex to prevStageIndex. On a mismatch, broadcasts a stage-change announcement and updates prevStageIndex. Also detects end-of-cycle (last stage → first stage) and resets State.cycleStartTime.

windTrend ()

Compares the oldest and newest entries in State.windHistory (a ring buffer of up to WIND_HISTORY_SIZE samples). Reports whether speed is rising, falling, or steady (threshold: 0.5 m/s), and whether direction is veering (clockwise), backing (anti-clockwise), or steady (threshold: 5°). Returns a formatted string e.g. "speed RISING +4 kts | veering 9°".

windVecToMet ( vec )

Converts a DCS Vec3 wind vector from atmosphere.getWind() into meteorological speed (m/s) and FROM-direction (degrees). Uses atan2(-x, -z) to get the direction the wind comes from, matching the METAR convention.

Customisation Recipes

Change cycle speed to 4 hours total

Only edit the startMin values in the script — nothing else needed:

startMin = 0,    -- CLEAR       (00:00–01:20)
startMin = 80,   -- BUILDING    (01:20–02:00)
startMin = 120,  -- THUNDERSTORM (02:00–02:40)
startMin = 160,  -- CLEARING    (02:40–03:20)
startMin = 200,  -- OVERCAST    (03:20–04:00)
startMin = 240,  -- CLEAR reset  (04:00 → loop)

Broadcast to all coalitions (red + blue + neutral)

BROADCAST_COALITION = 0,  -- 0 = all players

Increase warning lead time to 45 minutes

WARN_LEAD_TIME = 2700,  -- 45 × 60 seconds

Add a radio menu "Request ATIS" option

In the ME, add a trigger:

  • Condition: FLAG IS TRUE — any flag you assign to the radio menu item
  • Action 1: SET USER FLAG → Flag 10, Value 1
  • Action 2: SET FLAG OFF → clear your radio menu flag

Remove the thunderstorm entirely

Delete the THUNDERSTORM stage block from WEATHER_STAGES and adjust the remaining startMin values so they are still consecutive. No ME trigger changes needed.

Add a second ATIS reference point (e.g. carrier / FARP)

Duplicate the broadcastATIS call with a different point table, or add a second call to atmosphere.getWind() inside the function using a different Vec3 position, and append its data to the message.

Skip ATIS broadcasts — use warnings only

ATIS_INTERVAL = 999999,  -- effectively disabled

Troubleshooting

SymptomCauseFix
No weather messages appear at all Script did not load Check your MISSION START trigger has type DO SCRIPT FILE (not DO SCRIPT) and the file path is correct. Check DCS logs (Logs\dcs.log) for [DWC] entries.
Messages appear for Red coalition only BROADCAST_COALITION set to 1 Set BROADCAST_COALITION = 2 for Blue, or 0 for all.
Wind direction in ATIS reads 0° constantly AIRFIELD_REF coordinates are wrong or outside the map Re-check your airfield world coordinates from the ME. Ensure y = 0 (not altitude).
Warning fires multiple times for same stage Unlikely — only possible if script was reloaded mid-mission The State.warningsFired guard prevents duplicates within one cycle. If the script is re-triggered by a second MISSION START event, clear the guard by setting State.warningsFired = {}.
QNH reads standard 1013 hPa every time DCS is using static atmosphere Confirm the Weather tab has Atmosphere Type = Dynamic selected.
ATIS flag doesn't trigger broadcast Wrong flag number in CFG or ME trigger Both CFG.ATIS_FLAG and the ME SET USER FLAG action must use the same flag number (default: 10).

Reading the DCS log

The script writes status entries to the DCS log prefixed with [DWC]. Open %USERPROFILE%\Saved Games\DCS\Logs\dcs.log in a text editor and search for [DWC]. You'll see entries for initialisation, each ATIS broadcast, each stage transition, and each warning fired. 

-- Example log entries:
INFO    [DWC] DCS_DynamicWeatherCycle initialised at mission time 0
INFO    [DWC] ATIS broadcast at T+00:00
INFO    [DWC] Warning fired for stage 2 (BUILDING)
INFO    [DWC] Stage transition → BUILDING
INFO    [DWC] Warning fired for stage 3 (THUNDERSTORM)
