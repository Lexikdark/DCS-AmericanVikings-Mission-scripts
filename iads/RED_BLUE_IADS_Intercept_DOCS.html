RED / BLUE IADS + Intercept System

RED_BLUE_IADS_Intercept.lua  ·  Syria map  ·  Requires MIST 4.5

How It Works

Five parallel systems run simultaneously via DCS timer loops:

  1. IADS Network — EWR and SAM groups discover each other. EWR shares contacts to nearby SAMs. The SAM with the best engagement geometry fires.
  2. ARM Defence — an incoming-weapon tracking loop watches every in-flight weapon. If an ARM is detected heading for a radar, that radar shuts down and optionally moves.
  3. Air Intercept — trigger zones mark airspace sectors. When an enemy aircraft enters a zone, the assigned late-activate flight scrambles from the nearest base.
  4. GCI Picture — an AWACS/GCI controller broadcasts a contact summary to all coalition players on a timed interval.
  5. RTB Check — airborne intercept flights are monitored for fuel. At bingo they are ordered to RTB.
Both coalitions run independent but symmetrical copies of all five systems. RED has 8 squadrons, BLUE has 3. SAM and EWR groups for both sides are auto-discovered by naming prefix at startup and periodically refreshed.

Configuration — Update Intervals

Click any row to expand the detailed explanation.

UPDATE_INTERVAL10 sMain IADS loop — contact gathering, SAM engagement decisions.▼ details

Every UPDATE_INTERVAL seconds the script runs pruneDeadNodes() to remove destroyed SAMs/EWRs, then gatherContacts() for both coalitions, shares detections to SAM nodes, scores each SAM's engagement geometry, and fires the best shooter. This is the heartbeat of the entire IADS.

Performance note (Feb 2026): Changed from 5 s to 10 s. The main loop no longer calls buildNodeList() (which triggered 6× coalition.getGroups(GROUND) per tick). Instead, a lightweight pruneDeadNodes() removes dead groups from the existing lists without any API calls. Full node-list rebuilds only happen on the 15-minute nodeRefreshLoop. Additionally, gciInterceptLoop now caches coalition.getGroups(AIRPLANE) once per coalition per tick instead of calling it 21× per squadron.

Recommended range: 5–15 s. The default 10 s gives responsive SAM engagement while keeping API overhead low.

AIR_INTERCEPT_INTERVAL10 sHow often intercept zones are checked for enemy aircraft.▼ details

Every 10 seconds the script checks whether any enemy aircraft are inside any coalition trigger zones. If so, and if the assigned squadron has available (alive, not currently airborne) flights, one flight is scrambled.

10 s means up to a 10-second delay between an aircraft entering a zone and a scramble order. At 900 km/h an aircraft travels ~2.5 km in 10 s — increase the zone radius by that amount if you want zero-miss scrambles, or lower to 5 s for tighter response.

WEAPON_TRACK_INTERVAL2 sHow often in-flight weapons are scanned for ARM threats.▼ details

Every 2 seconds the script iterates every weapon in trackedWeapons[]. It checks: is this weapon still alive? Is it an ARM type? Is it heading towards any of our radar groups? If yes, that radar shuts down for ARM_SHUTDOWN_TIME seconds.

2 seconds is responsive enough for ARM tracking — ARMs typically fly for 20–60 seconds so sub-second tracking has no benefit. The previous 1 s interval was halved to reduce the tracking cost during large engagements with many in-flight weapons while maintaining fully reactive ARM defence.

RTB_CHECK_INTERVAL15 sHow often airborne intercept flights are checked for bingo fuel.▼ details

Every 15 seconds all active (airborne) intercept flights are checked. For each flight, every unit's Unit:getFuel() is called, which returns a 0.0–1.0 fraction of internal fuel capacity. If any unit is at or below GCI_FUEL_RTB_THRESHOLD the flight is ordered to RTB.

15 s is a reasonable polling rate. Fuel burn is slow enough that a 15-second gap between checks won't cause a flight to flame out before receiving the RTB order. Lower to 5 s for very short-range aircraft.

NODE_REFRESH_INTERVAL900 s (15 min)How often the SAM and EWR node lists are fully rebuilt from scratch.▼ details

On startup buildNodeList() scans all coalition ground groups and builds the SAM and EWR node lists from naming prefixes. Every 15 minutes it runs again to pick up any dynamically spawned groups.

Dead-node handling: Between full rebuilds, the main IADS loop (every UPDATE_INTERVAL) calls pruneDeadNodes() which iterates the existing node lists and removes any group whose :getSize() returns 0 or whose :isExist() returns false. This is a lightweight check with no coalition.getGroups() API calls, keeping the lists current without waiting for the 15-minute rebuild.

Reduce to 300 s for fast-paced missions with rapid SAM losses. Increase to 1800 s on low-spec servers.

Configuration — Detection

USE_DCS_DETECTIONtrueToggle between realistic DCS radar model and simple range-sphere detection.▼ details

When true, the primary detection pass uses coalition.getDetectedTargets(coaID, Unit.SensorType.RADAR) — the same contact list DCS itself uses for the AI. This respects: radar line-of-sight, terrain masking, aircraft RCS, ECM jamming, altitude-induced terrain masking, and RCS modifiers.

When false, only the secondary fallback (range-sphere geometry check) runs. Every aircraft within EWR_DETECTION_RANGE of any live EWR node is detected regardless of terrain or ECM.

Recommendation: Leave true for realistic play. The secondary sphere check always runs in addition to supplement the DCS sensor model — it never replaces the primary pass. This ensures AWACS gets its extended reach and no contacts fall through gaps.

EWR_DETECTION_RANGE250,000 m (250 km)Radius within which a ground EWR node shares contacts to SAMs.▼ details

EWR nodes (e.g. 1L13 Nebo, P-19, TPS-75) share their contacts to all SAM nodes within this radius. This value is used in the secondary sphere fallback and as the IADS network sharing radius.

SAM nodes themselves contribute to detection at 60% of this value (EWR_DETECTION_RANGE * 0.6 = 150 km by default) reflecting their shorter-range organic radars. AWACS nodes use the separate AWACS_DETECTION_RANGE.

250 km is realistic for a long-range surveillance radar. Reduce if you want EWR blind spots that SEAD can exploit by destroying forward EWR nodes before striking SAMs further back.

SAM_ENGAGE_SHARE_RANGE180,000 m (180 km)How far a SAM shares targeting data to other SAMs for cooperative engagement.▼ details

When a SAM has a qualified contact it shares targeting to all other SAMs within this radius. Those SAMs add the shared contact to their engagement queue and are scored against it. This creates a cooperative IADS where destroying one SAM doesn't leave a gap — adjacent SAMs receive the handoff.

180 km is representative of how integrated an S-300 / S-400 battery network operates. Reduce to 80–100 km for a simpler network where each battery operates more independently.

AWACS_DETECTION_RANGE420,000 m (420 km)Detection radius contributed by airborne AWACS / AEW aircraft.▼ details

Any group matching RED_AWACS_ or BLUE_AWACS_ that is airborne contributes a detection sphere of this radius in the secondary fallback pass. 420 km represents a realistic AEW radar surveillance range for an E-3 / A-50 class aircraft at high altitude.

When USE_DCS_DETECTION = true, the DCS sensor model already gives the AWACS its own radar-realistic detections; this value supplements to catch any gaps. If you don't use AWACS in your mission, simply don't name any groups with the AWACS prefix — the range value has no effect if no matching groups exist.

Configuration — SAM Engagement

SAM_MIN_ENGAGE_ALT30 m AGLMinimum altitude for a contact to be considered a valid SAM target.▼ details

Contacts below this altitude (metres, from pos.y) are filtered out of the engagement queue. This prevents the IADS from fixating on ground vehicles, boats, or aircraft that are taxiing. 30 m is one building-height above ground — effectively only airborne threats qualify.

Raise to 100 m if you want the IADS to ignore nap-of-earth helicopter ingress. Set to 0 to let SAMs engage anything including vehicles (rarely useful).

SAM_FIRE_DELAY_MIN / MAX2 – 8 sRandom reaction delay before a SAM fires once it has a valid firing solution.▼ details

Once a SAM wins the engagement scoring contest, a random delay between SAM_FIRE_DELAY_MIN and SAM_FIRE_DELAY_MAX is applied before the actual fire order. This prevents all SAMs firing simultaneously in the same DCS frame, which looks unnatural and can cause missile spawn issues.

The randomness also makes the IADS feel less mechanical — sometimes the missile comes quickly, sometimes there's a brief hesitation. Raise the max to 15 s for a noticeably sluggish network; lower the min to 0 for instantaneous response.

PKill_BASE0.75Base probability-of-kill used in the SAM scoring formula.▼ details

The engagement scoring formula is: score = PKill_BASE × altFactor × rangeFactor × healthFactor. The SAM with the highest score engages. PKill_BASE is the baseline for a healthy SAM unit with the target perfectly on boresight at optimal range.

Factors reduce the score: targets at very low altitude drop altFactor, targets near the edge of range drop rangeFactor, damaged SAMs drop healthFactor. The score is relative — it determines which SAM gets the shot, not whether the missile actually hits (that's DCS's own miss calculation).

Changing PKill_BASE doesn't make SAMs more or less lethal in isolation; it shifts the scoring baseline and affects which SAM gets selected when multiple equally-positioned SAMs compete for the same target.

SAM_MIN_ENGAGE_SCORE0.35Minimum Pk score a SAM needs before it will fire. Prevents wasted shots.▼ details

After the scoring formula computes a value for every SAM–contact pair, the result is compared to this threshold. If the score is below it, the SAM holds fire regardless of whether it is the best available shooter. This prevents damaged SAMs at extreme range from wasting missiles on hopeless shots.

At the default 0.35, any target flying at normal bombing altitude (above ~500 m / 1,600 ft) will be engaged at essentially full range. The threshold only filters junk shots: crippled batteries, extreme distances, and very low altitude targets at long range.

ValueBehaviour
0.05Fire at almost anything detected (old default). Wastes missiles.
0.25Skip truly hopeless shots (extreme range + low alt + damaged).
0.35Recommended. Solid engagement solution required. No gaps against normal attack profiles.
0.50Disciplined — holds until near-optimal geometry. Damaged SAMs become noticeably less effective.

Configuration — Low-Altitude Jet Immunity

Simulates radar ground-clutter masking: fixed-wing aircraft (jets) flying very low are invisible to long-range RED SAMs but remain visible to SHORAD groups. This gives pilots a meaningful tactical choice — fly low to dodge SA-5/SA-10 but risk running into Pantsir / Shilka / Tor SHORAD sites that are specifically designed for low-altitude targets.

SAM_LOW_JET_IMMUNITY_AGL75 m AGLJets below this altitude are invisible to non-SHORAD RED SAMs.▼ details

When the IADS gathers radar contacts, each detected unit is checked:

  1. Is this a RED or LEBANON IADS network? (BLUE SAMs are unaffected.)
  2. Is the contact a fixed-wing aircraft (Unit.Category.AIRPLANE)? Helicopters are always visible.
  3. Is the contact’s AGL altitude (terrain-aware: pos.y − land.getHeight(x,z)) below this threshold?

If all three conditions are true, the contact is tagged isLowJet = true. The contact stays in the contact list (so SHORAD can see it) but when the engagement loop assigns SAMs, any SAM whose group name does not contain "SHORAD" will skip the contact.

How SHORAD is detected

The script checks if the SAM group’s name contains the string "SHORAD" (case-sensitive). This relies on your existing naming convention:

RED_SAM_SHORAD_Pantsir_01   ← contains "SHORAD" → EXEMPT (engages low jets)
RED_SAM_S300_Battery_01     ← no "SHORAD"       → SKIPS low jets
RED_SAM_SHORAD_Tor_02       ← contains "SHORAD" → EXEMPT

Naming matters! If a SHORAD group is named RED_SAM_Pantsir_01 (without “SHORAD” in the name), it will not be exempt and will ignore low-flying jets. Make sure all short-range air-defence groups include SHORAD in their ME group name.

Configuration — ARM Defence

ARM_SHUTDOWN_TIME45 sHow long a radar stays silent (EMCON) after detecting an incoming ARM.▼ details

When the weapon tracking loop detects an ARM-class weapon within a threat threshold of a radar group, it orders that radar to stop emissions and records the suppression end time. For the next 45 seconds that group is skipped in SAM engagement scoring even if a non-ARM aircraft is in view.

45 seconds is realistic for a trained SAM crew's EMCON response. AGM-88 HARM flies ~100 km in about 45–60 seconds, so this value roughly matches the weapon's flight time, giving the radar a realistic window to go dark before impact.

Reduce to 20 s for a less cautious crew. Increase to 90 s to make SEAD missions very punishing — the SAM will be dark for the entire follow-on strike window.

ARM_MOVE_RADIUS800 mDistance a mobile SAM randomly relocates when an ARM is detected.▼ details

If the targeted SAM group contains mobile units (e.g. Pantsir, Buk, S-300 TELs) this value defines the radius of the random relocation offset applied when an ARM is detected. The group moves to a random point within this radius of its current position.

800 m is enough to cause a HARM with a ~50 m CEP to miss. Increase to 1500–2000 m for a more dramatic scoot response, but note that large moves on hilly terrain may place a unit in an obstacle — DCS doesn't pathfind random moves.

For static sites (e.g. fixed S-300 launchers) this value is irrelevant because the movement command is ignored by non-mobile units.

Configuration — Air Intercept

INTERCEPT_ALTITUDE6,000 mAltitude (metres) assigned to scrambled intercept flights.▼ details

When a flight is scrambled, their intercept waypoint is set to this altitude. 6,000 m (approximately FL200) is a good medium-high intercept altitude for most threats — above most Man-PAD / AAA while below typical BARCAP altitudes.

Increase to 8,000–10,000 m for threats that fly at medium-high altitude (cruise missiles, strike packages). Decrease to 4,000 m for a low-altitude intercept role.

INTERCEPT_SPEED900 km/hSpeed (km/h) set for intercept waypoints.▼ details

The indicated airspeed set on the intercept waypoint. 900 km/h is a reasonable intercept speed for most fighter aircraft — fast enough to close quickly without burning excessive fuel. Increase to 1,100+ km/h for more aggressive intercepts. DCS AI may ignore this value if it exceeds the aircraft's max speed.

RTB_LOITER_TIME120 sHow long a flight loiters after the threat zone clears before RTB is ordered.▼ details

After an intercept zone goes empty (no more enemy contacts), the script waits this many seconds before checking again. If still empty, RTB is ordered. This prevents flights from immediately bugging out the moment a contact briefly drops off radar only to return 10 seconds later.

120 s (2 minutes) provides enough buffer for a momentarily-lost contact to reappear. Reduce to 60 s for aggressive immediate RTB. Increase to 300 s if you want fighters to patrol after clearing a zone.

ZONE_PREFIX"RED_ZONE_"Naming convention prefix for airspace sector trigger zones.▼ details

Each squadron in SQUADRONS.RED has a zone field that must match a DCS trigger zone name exactly. The prefix is a convention you must follow when naming zones in the ME — it is not auto-prepended. Example: zone field "RED_ZONE_DAMASCUS" must exactly match a trigger zone of that name in the mission file.

Use circles, not polygons. The script reads zd.radius and zd.point from MIST's zone database and performs a simple 2D distance check — it does not use DCS's native polygon inside/outside test. For a polygon zone MIST provides the bounding-circle radius (centre to furthest vertex), so the actual polygon shape is ignored and the check is always circular. A long thin polygon will behave like a large circle enclosing it, triggering scrambles for contacts that are geometrically outside the polygon but inside its bounding circle. Stick to circle zones for correct behaviour.

Configuration — GCI / AWACS

GCI_PICTURE_INTERVAL180 s (3 min)How often AWACS broadcasts a contact picture to all coalition players.▼ details

Every 180 seconds the script compiles a summary of all currently tracked enemy contacts and broadcasts it to all players on that coalition via trigger.action.outTextForCoalition. The message is prefixed with the callsign defined in AWACS_CALLSIGN (RED = "OVERLORD", BLUE = "MAGIC").

The picture includes contact count, approximate bearing and distance from an AWACS reference point, and altitude band. 3 minutes is a realistic AEW reporting cycle. Reduce to 60 s for faster-paced air warfare. Set to a very high value (99999) to effectively disable automatic pictures while keeping AWACS detection contribution active.

GCI_FUEL_RTB_THRESHOLD0.20 (20%)Fuel fraction at which an intercept flight is ordered to RTB.▼ details

The threshold is compared against Unit:getFuel() which returns a 0.0–1.0 fraction of internal fuel. External tanks are NOT included — DCS's getFuel() only reports internal fuel regardless of loadout. A Hornet with drop tanks may actually have far more total fuel than the script can detect.

0.20 (bingo 20%) is reasonable for most aircraft to still complete a divert. Extend to 0.30 for short-range aircraft (MiG-21, Harrier). The threshold is checked per unit, not per group — if any unit in the flight hits bingo, the entire group is called RTB.

AWACS_CALLSIGN / GCI_CALLSIGNOVERLORD / MAGICRadio callsign strings used in player-facing GCI and picture messages.▼ details

These strings are prepended to all GCI picture broadcasts and intercept control messages. They are purely cosmetic — they don't affect any game mechanics. Change to match your mission's radio narrative. GCI_CALLSIGN is used for scramble/RTB orders; AWACS_CALLSIGN for the periodic picture broadcasts.

AWACS_CALLSIGN = { RED = "OVERLORD", BLUE = "MAGIC" }
GCI_CALLSIGN   = { RED = "GCI MOSCOW", BLUE = "GCI CONTROL" }

System Deep-Dive — Detection Pipeline

Contact gathering runs every UPDATE_INTERVAL seconds via gatherContacts(coaName, enemyCoa). Two passes run in sequence; results are deduplicated by unit name in a seen table.

Pass 1 — DCS Radar Model (when USE_DCS_DETECTION = true)

coalition.getDetectedTargets(myCoaID, Unit.SensorType.RADAR) returns an array of detected objects. The script filters for: alive, enemy coalition, altitude > SAM_MIN_ENGAGE_ALT, not already in seen list. Each valid contact is stored with its position, velocity, detection time, and a byRadar = true flag.

Pass 2 — Range Sphere Supplement (always runs)

Every live EWR node, SAM node, and AWACS aircraft is used as a detection origin. Every enemy aircraft within that node's detection radius is added if not already seen. Detection radii:

  • EWR nodes: EWR_DETECTION_RANGE (250 km default)
  • SAM nodes: EWR_DETECTION_RANGE * 0.6 (150 km default)
  • AWACS aircraft: AWACS_DETECTION_RANGE (420 km default)

System Deep-Dive — SAM Scoring & Engagement

After contacts are gathered, each contact is scored against each live SAM node. The engagement sequence:

  1. For each contact, find all SAM nodes within SAM_ENGAGE_SHARE_RANGE.
  2. For each candidate SAM compute: score = PKill_BASE × altFactor × rangeFactor × healthFactor
  3. The SAM with the highest score that is not currently suppressed (suppressedUntil[name] < timer.getTime()) gets the fire order.
  4. A random delay of SAM_FIRE_DELAY_MIN to SAM_FIRE_DELAY_MAX is applied before the controller fires.
The script assigns fire orders but DCS's AI SAM controller ultimately decides whether to launch. If the target leaves the SAM's engagement envelope before the delay expires, the fire order may be ignored. This is correct behaviour.

System Deep-Dive — Pk Threshold Gate

The SAM_MIN_ENGAGE_SCORE constant (default 0.35) acts as a quality gate on every engagement. A SAM will only fire when its computed score exceeds this value. This section explains exactly how the scoring formula works and what each threshold level means for real DCS combat scenarios.

The Scoring Formula

Score = PKill_BASE (0.92) × rangeFactor × altFactor × healthFactor

Each factor runs from 0.0 to 1.0. They multiply together, so one bad factor drags the whole score down.

Peaks at 40% of SAM_ENGAGE_SHARE_RANGE (180 km) = 72 km (the sweet spot). Falls off at both extremes.

Bottom line: At 0.35, a player flying at any normal bombing altitude (above ~1,600 ft / 500 m) will get engaged at effectively full range — the threshold doesn’t protect them at all. What it does do is stop damaged SAMs from wasting missiles at hopeless targets, and makes low-altitude ingress actually rewarding (you get closer before they shoot, but they still shoot once you’re in a reasonable envelope).
The 75 m AGL jet immunity (SAM_LOW_JET_IMMUNITY_AGL) is separate and still applies — that’s the hard floor for terrain masking against non-SHORAD SAMs. The Pk threshold gate operates above that floor.

System Deep-Dive — ARM Defence

The 1-second weapon tracking loop iterates all in-flight weapons found via world.searchObjects. For each weapon:

  1. Check its type name against ARM_TYPES using string.find() partial match — catches both underscore and hyphen DCS naming variants.
  2. If it is an ARM, compute its velocity vector to estimate the aim point.
  3. For each live radar group within the estimated impact corridor, trigger EMCON: record suppressedUntil[group] = timer.getTime() + ARM_SHUTDOWN_TIME.
  4. If the group has mobile units, apply a random positional offset up to ARM_MOVE_RADIUS.
  5. The suppressed group is skipped in the SAM scoring loop until the suppression expires.

Both ARM_TYPES and AGM_TYPES lists include dual-form DCS names (e.g. "AGM_88" and "AGM-88") to handle DCS version differences in weapon type-name formatting.

System Deep-Dive — Air Intercept Scramble

The 10-second intercept loop:

  1. For each zone, look up zd.point (zone centre) and zd.radius from MIST's zone database, then do a 2D distance check: dist2d(contact.pos, zd.point) ≤ zd.radius + 80,000 m (80 km threat buffer). This is always a circle test — polygon zone shapes are not respected; only the bounding-circle radius from MIST is used.
  2. If any enemy is in the zone and the squadron's current airborne count is below maxFlights, find the next available (alive, not yet activated) group with the squadron's groupPrefix.
  3. Activate the group via group:activate() and assign waypoints: climb to INTERCEPT_ALTITUDE, intercept point over the zone centre, then RTB waypoint at homeBase.
  4. The flight is added to the active flights list for monitoring by the RTB loop.

Pool exhaustion: when all numbered groups for a prefix are used (dead or activated), no more scrambles occur. This is intentional — the IADS has a finite aircraft per base. Add more ME late-activate groups to increase the total sortie count.

System Deep-Dive — GCI Picture Broadcast (Per-Pilot BRAA)

Every GCI_PICTURE_INTERVAL seconds the script compiles a contact summary from state.contacts and delivers a personalised BRAA (Bearing, Range, Altitude, Aspect) picture call to each individual Blue pilot. Bearings and ranges are computed from each pilot’s own position, not from the AWACS.

How It Works

  1. Confirms at least one BLUE_AWACS_* group is alive — if not, no picture is broadcast (AWACS is the “sender” even though BRAA is pilot-relative).
  2. Contacts are grouped by DCS flight group — each group’s centroid position and highest altitude are pre-computed once (shared across all pilots).
  3. Uses coalition.getPlayers(BLUE) to get every player-controlled Blue aircraft currently alive.
  4. For each player, computes bearing and range from that pilot’s current position to each contact group centroid.
  5. Sends the message only to that pilot’s group via trigger.action.outTextForGroup() — no other players see it.

Example Broadcasts

Two pilots in different locations see different BRAA for the same contacts:

[MAGIC]  Viper1-1, PICTURE — 2 group(s):
  RED_CAP_DAMASCUS_01  BRAA 045° / 62 nm  Angels 25
  RED_CAP_HAMA_02 x2   BRAA 350° / 41 nm  Angels 18

Performance note: Contact grouping and altitude calculations are done once per tick. Only the bearing / range math is repeated per pilot. With 20 players and 10 contact groups the per-tick cost is ~200 trig calls — negligible.

System Deep-Dive — RTB & Fuel Check

Every RTB_CHECK_INTERVAL seconds, for each active (airborne) flight:

  1. Iterate every unit in the group. Call unit:getFuel() which returns 0.0–1.0 (internal fuel only).
  2. If any unit's fuel ≤ GCI_FUEL_RTB_THRESHOLD, issue RTB waypoints back to homeBase and broadcast "[callsign] BINGO. RTB." to the coalition.
  3. If the zone has been clear (no contacts) for ≥ RTB_LOITER_TIME, also issue RTB even if fuel is sufficient.
  4. Despawn/removal from active list occurs when DCS reports all units dead or when the group lands at the home base (altitude <10 m, speed <10 km/h near base).

System Deep-Dive — Node List Refresh

On startup and every NODE_REFRESH_INTERVAL seconds, buildNodeList() runs:

  1. Clears state.samNodes and state.ewrNodes.
  2. Calls coalition.getGroups(coaID, Group.Category.GROUND) — returns all live ground groups.
  3. Filters by prefix string matching, then checks groupAlive(name) (at least one unit with health >1%).
  4. Logs the counts: [IADS] RED IADS: 12 SAM nodes, 4 EWR nodes

  1. Load order — MISSION START → DO SCRIPT FILE: mist_4_5_126.lua then RED_BLUE_IADS_Intercept.lua
  2. SAM groups — name all RED SAM groups RED_SAM_*, BLUE groups BLUE_SAM_*. Can be active at start.
  3. EWR groups — name as RED_EWR_* / BLUE_EWR_*. Active at start.
  4. AWACS — name groups RED_AWACS_* / BLUE_AWACS_*. Can be active or pre-flighted.
  5. Air intercept flights — set all RED_AIR_* / BLUE_AIR_* groups to Late Activation. Number them _01, _02 etc.
  6. Trigger zones — place one trigger zone per squadron, named exactly as the zone field (e.g. RED_ZONE_DAMASCUS).
  7. Zone shape — always use circles. The script does a radius-based distance check using zd.radius from MIST — it does not honour polygon geometry. Quick test: in dcs.log search for [IADS]. Within the first seconds of mission load you should see node counts for RED and BLUE. If you see 0 SAM nodes, check your group naming.

Function Reference — SAM Engagement

These three functions form the SAM brain: scoring, assigning, and firing.

computeEngagementScore(samName, contact) → numberinternal▼ details

Calculates a 0.0–1.0 probability-of-kill score for a SAM engaging a specific contact. Returns 0 immediately if the SAM is currently suppressed (suppressedUntil not expired) or the contact is beyond SAM_ENGAGE_SHARE_RANGE. The score drives which SAM wins the engagement assignment in optimizeEngagements().

Score formula: PKill_BASE × rangeFactor × altFactor × healthFactor

  • rangeFactor — peaks at 40% of SAM_ENGAGE_SHARE_RANGE; falls off at close range and beyond. Minimum 0.05.
  • altFactor — 1.0 for 500–12,000 m AGL. Ramps down linearly below 500 m (nap-of-earth penalty) and above 12,000 m (high-altitude penalty). Clamped to 0.1–1.0.
  • healthFactor — ratio of alive units to total units in the SAM group. A one-launcher Pantsir with all missiles expended still scores; a half-destroyed battery scores 0.5×.
ParamTypeNotes
samNamestringSAM group name from IADS[coaName].samNodes.
contactcontact tableEntry from IADS[coaName].contacts.

Returns: number 0.0–~0.75 (0 = cannot or should not engage)

Turns the SAM's radar on (setOnOff(true)) and pushes an EngageUnit task to its controller targeting the specific contact. The DCS AI SAM controller then decides whether to launch and how many missiles to use. The script does not override the DCS engagement model — it only provides the targeting assignment.

Uses weaponType = 268402688 (all weapons auto-select) and expend = "Auto" so the battery manages its own ammo conservation.

optimizeEngagements(coaName)internal▼ details

The IADS engagement brain. Runs a full contacts × SAM scoring matrix every tick:

  1. For each contact in IADS[coaName].contacts, calls computeEngagementScore() across all SAM nodes.
  2. The highest-scoring un-suppressed SAM for each contact wins, and receives a randomised delayed orderSAMEngage() call after SAM_FIRE_DELAY_MIN–SAM_FIRE_DELAY_MAX seconds (simulates battery reaction time).
  3. SAM nodes with no assigned contact are put into radar standby (setOnOff(false)) to reduce SEAD exposure.

Multiple contacts can map to the same SAM if there are fewer SAMs than contacts — the same battery can win multiple scoring contests in the same tick. The assignment is re-computed from scratch every UPDATE_INTERVAL.

Function Reference — ARM / AGM Defence

Three functions handle inbound anti-radiation missiles and other guided munitions.

Function Reference — Event Handler

eventHandler:onEvent(event)world event handler▼ details

The DCS world event handler registered once at startup via world.addEventHandler(eventHandler). Processes two event types:

S_EVENT_SHOT — fires when any unit launches a weapon. The handler:

  1. Gets the weapon type name via wpn:getTypeName().
  2. Checks it against IADS_CFG.ARM_TYPES and IADS_CFG.AGM_TYPES using string.find() partial match — so "HARM" in ARM_TYPES will match "AGM_88C_HARM".
  3. If it matches, determines the defending coalition from the initiator's coalition side.
  4. Appends an entry to trackedWeapons[] with the weapon object, ARM/AGM type flags, defending coalition name, and the detection timestamp.

S_EVENT_DEAD / S_EVENT_CRASH — fires when a unit is killed or crashes. Checks if the unit belongs to a tracked intercept flight and marks that flight's status as "dead" in gciState[coalName].flights.

The event handler feeds trackedWeapons[] and flight status tables. It does not directly suppress radars or order RTBs — those actions happen in the timer loops that consume this data.

Function Reference — Timer Loops

Five self-rescheduling timer callbacks drive all runtime behaviour. Each returns its own next execution time via the DCS timer.scheduleFunction() API.

weaponTrackingLoop() → nextTimetimer — 1 s▼ details

Runs every WEAPON_TRACK_INTERVAL (1 s — the fastest loop). Iterates trackedWeapons[]. For each tracked weapon:

  • Calls wpn:getPoint() inside pcall(). If the call fails or returns nil, the weapon has impacted or expired and is dropped from the list.
  • ARM weapons not yet alerted: calls findARMTarget(); if miss distance < 80 km, calls suppressSAMRadar() and sets wt.alerted = true to prevent repeated suppression.
  • AGM weapons: calls alertSHORADtoEngageWeapon() every tick — continuously re-alerts nearby SHORAD as the weapon approaches.

At the end of each tick, trackedWeapons is replaced with the filtered active-only array.

Returns: timer.getTime() + WEAPON_TRACK_INTERVAL

iadsUpdateLoop() → nextTimetimer — 5 s▼ details

The main IADS heartbeat. Runs every UPDATE_INTERVAL (5 s). Each tick performs the full detection-to-engagement pipeline for both coalitions in sequence:

  1. buildNodeList() × 2 — refreshes SAM/EWR node arrays, dropping killed groups.
  2. gatherContacts() × 2 — rebuilds both contact lists from scratch using dual-pass detection.
  3. optimizeEngagements() × 2 — scores and assigns SAM engagements for all contacts.

Returns: timer.getTime() + UPDATE_INTERVAL

gciInterceptLoop() → nextTimetimer — 10 s▼ details

Runs every AIR_INTERCEPT_INTERVAL (10 s). For each coalition, for each configured squadron:

  1. Checks if a picture broadcast is due (now − lastPicture ≥ GCI_PICTURE_INTERVAL); if so calls broadcastPicture() and resets the timer.
  2. Calls getThreatsForZone() for the squadron's assigned zone.
  3. Threats present: resets clearSince; computes need = min(threats, maxFlights) − countAirborne(); calls dispatchFlight() for each needed scramble.
  4. No threats, flights airborne: starts or advances clearSince. Once clearSince ≥ RTB_LOITER_TIME, calls orderFlightRTB() for every airborne flight in the squadron.

Returns: now + AIR_INTERCEPT_INTERVAL

flightMaintenanceLoop() → nextTimetimer — 15 s▼ details

Runs every RTB_CHECK_INTERVAL (15 s). Iterates all flights marked "airborne" in both coalition flight registries. For each:

  • Verifies the DCS group still exists. If not → marks status "dead".
  • Iterates alive units tracking the lowest fuel fraction via unit:getFuel() (0.0–1.0, internal tanks only).
  • If no alive units → marks status "dead".
  • If lowestFuel ≤ GCI_FUEL_RTB_THRESHOLD → calls orderFlightRTB() with a bingo message including the actual percentage.

Returns: timer.getTime() + RTB_CHECK_INTERVAL

nodeRefreshLoop(_, time) → nextTimetimer — 900 s▼ details

Runs every NODE_REFRESH_INTERVAL (900 s / 15 min). Calls buildNodeList() for both coalitions — the definitive cleanup pass that permanently removes any SAM or EWR group destroyed since the previous full refresh. While iadsUpdateLoop() also calls buildNodeList() every 5 s for incremental updates, nodeRefreshLoop() serves as the authoritative long-period rebuild ensuring no stale entries persist.

Returns: time + NODE_REFRESH_INTERVAL

  3. Hardcoded Syria map centre fallback: {x = -110000, y = 500, z = 50000} — used if both lists are empty.

Function Reference — Per-Pilot BRAA Picture Broadcast

broadcastPicture(coalName)internal — called from gciInterceptLoop▼ details

Generates and delivers personalised BRAA picture calls to every online pilot in the coalition. Each pilot receives bearings and ranges computed from their own aircraft position, not a shared AWACS reference.

Execution Flow

  1. Confirms at least one AWACS group (matching AWACS_PREFIX) is alive — if not, silently skips the entire broadcast.
  2. Retrieves all online human players for the coalition via coalition.getPlayers(coaEnum).
  3. For each player unit that is alive:
    • If contacts exist: calls contactPicture(contacts, pilotPos) using the pilot's own position as the reference point, then sends a personalised message via trigger.action.outTextForGroup().
    • If no contacts: sends a "PICTURE CLEAR" message to that pilot's group.
  4. If fewer than IADS_CFG.GCI_MIN_CONTACTS contacts exist, the broadcast is suppressed entirely (same gate as before).

Messages display for 16 seconds. Example per-pilot broadcasts:

[OVERLORD → Viper1]  BRAA PICTURE: 3 contact(s), 045° / 32 nm, 2 high, 1 medium.
[OVERLORD → Hawg3]   BRAA PICTURE: 3 contact(s), 310° / 67 nm, 2 high, 1 medium.
[MAGIC   → Flanker1] BRAA PICTURE CLEAR. No enemy contacts.

API Change from v2.0

Prior to the per-pilot upgrade, broadcastPicture() used trigger.action.outTextForCoalition() with a single AWACS-relative bearing. The new version iterates players and calls trigger.action.outTextForGroup() once per pilot, yielding unique bearings per airframe.

ParamTypeNotes
coalNamestring"RED" or "BLUE"

Returns: nothing (side-effect: one HUD message per online pilot)

getThreatsForZone(zoneName, coaName) → tableinternal▼ details

Returns all enemy contacts within the zone's detection threshold. Reads the zone definition from mist.DBs.zonesByName[zoneName] (fields zd.point and zd.radius), then filters IADS[coaName].contacts using: dist2d(contact.pos, zd.point) ≤ zd.radius + 80,000 m.

The 80 km buffer means approaching threats trigger scrambles before breaching the zone boundary, giving intercept flights time to climb and position. The check is a circle only — polygon-shaped trigger zones are handled as their MIST-stored radius, not their actual shape.

ParamTypeNotes
zoneNamestringExact trigger zone name (e.g. "RED_ZONE_DAMASCUS").
coaNamestring"RED" or "BLUE"

Returns: array of contact tables (may be empty)

Polygon zones ignored: MIST only stores a radius for trigger zones. Polygon zones get a radius derived from their bounding circle. Always use circular trigger zones for reliable intercept sectors.

Function Reference — Scramble & RTB

dispatchFlight(groupName, coalName, sqd, threats, gciSt)internal▼ details

Activates a late-activate intercept group, registers it as airborne, broadcasts the scramble call, and assigns the intercept task. Full sequence:

  1. Activate — group:activate() spawns the group from late-activate state.
  2. Register — adds an entry to gciSt.flights[groupName] with status "airborne", zone, homeBase, callsign, coalition, and launch time.
  3. Broadcast — calls gciMsg() with a scramble message including the threat picture from contactPicture() and hostile count.
  4. Delayed task (4 s) — a timer fires 4 seconds after activation. Sets ROE weapons free (option 0 → 2) and aggressive threat reaction (option 1 → 0). If a live threat unit is available → EngageUnit. If not → Orbit over zone centre at INTERCEPT_ALTITUDE and INTERCEPT_SPEED.

The 4-second delay is required because the group controller may not be ready immediately after activate() — tasking too quickly results in tasks being silently dropped by DCS.

ParamTypeNotes
groupNamestringLate-activate group name (e.g. "RED_AIR_DAMASCUS_01").
coalNamestring"RED" or "BLUE"
sqdsquadron tableProvides zone name, homeBase, callsign.
threatsarrayContacts from getThreatsForZone(). First entry is the primary target.
gciSttablegciState[coalName]

Returns: nothing

orderFlightRTB(groupName, gciSt, reason)internal▼ details

Orders an airborne intercept flight to return to base and eventually despawn. Full sequence:

  1. Resolves fState.homeBase via Airbase.getByName(); falls back to getNearestAirbase() if not found.
  2. Sets ROE to return-fire only (option 0 → 4).
  3. Pushes a two-waypoint Mission task: current position → Landing at home airbase.
  4. Marks flight status "rtb".
  5. Broadcasts GCI RTB radio call with the reason string.
  6. Schedules a cleanup timer +600 s (10 min). When it fires, if status is still "rtb": calls group:destroy() and sets status to "standby", making the group name available for a future scramble cycle.
ParamTypeNotes
groupNamestringAirborne group to recall.
gciSttablegciState[coalName]
reasonstring or nilShown in GCI call and log — e.g. "Zone clear.", "Bingo fuel (19%)."

Returns: nothing

After the 600 s cleanup the group is destroyed in DCS, not returned to late-activate state. For reliable multi-sortie cycles, add additional late-activate intercept groups in the ME.

Function Reference — Initialisation

init()startup — runs at T+1 s▼ details

Master initialisation. Called via a 1-second delayed timer (at the bottom of the script) to ensure MIST is fully loaded before any IADS logic executes. Sequence:

  1. Seeds math.random with os.time() for randomised SAM fire delays and move offsets.
  2. Validates MIST is loaded — logs the MIST version to dcs.log.
  3. Calls discoverZones() — registers all prefixed trigger zones from MIST DB.
  4. Calls buildNodeList() for both RED and BLUE — populates initial SAM/EWR node arrays.
  5. Schedules the four runtime timer loops with staggered offsets to avoid simultaneous execution:
    • weaponTrackingLoop at T+5 s
    • iadsUpdateLoop at T+10 s
    • gciInterceptLoop at T+15 s
    • flightMaintenanceLoop at T+30 s
  6. Schedules nodeRefreshLoop at T+900 s (first full node rebuild at 15 min).
  7. Broadcasts "RED/BLUE Integrated Air Defence + Red Air Intercept ACTIVE" to all players.

Returns: nothing
