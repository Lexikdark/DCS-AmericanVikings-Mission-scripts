DGSS CTLD + JTAC System

DGSS-CTLD-JTACv7.2.lua  ·  Combat logistics, troop transport & autonomous JTAC laser designation

How It Works

Two systems share one script:

  1. CTLD (Combat Transport & Logistics) — players pick up troop teams or vehicles from designated CTLD zones and deploy them anywhere on the battlefield via F10 menu.
  2. JTAC (Joint Terminal Attack Controller) — once a JTAC team or vehicle is deployed, it autonomously scans a 10 km radius, finds the nearest RED enemy, lases it with a unique 4-digit laser code, and broadcasts a 9-line CAS callout. Players can override target selection from the JTAC Control menu.
Standalone laser system: The script implements its own ctld namespace using the native DCS Spot API — no external CTLD library is required. Both a visible laser spot (weapon lock-on) and an IR pointer (FLIR compatible) are created.

Config — Hard Limits

MAX_JTAC_TEAMS10Maximum JTAC infantry teams allowed on the map simultaneously.▼ details

Enforced at spawn time. The script counts only existing groups (verified via Group.getByName), so dead teams free a slot automatically. Raise to allow larger collaborative operations; lower to reduce server load on busy servers.

MAX_JTAC_VEHICLES10Maximum JTAC designated vehicles allowed simultaneously.▼ details

Separate limit from infantry teams. Applies to ground vehicle assets that double as JTAC platforms (e.g. HMMWV, MATV with laser). Dead or despawned vehicles free a slot.

Config — Troop & Vehicle Templates

Templates are defined in DGSS_CTLD.TROOP_TEMPLATES and DGSS_CTLD.VEHICLE_TEMPLATES. Each entry has:

FieldTypeDescription
namePrefixstringUsed to generate unique group names (e.g. "JTAC_Team")
displayNamestringHuman-readable name shown in the F10 menu
categorystringMenu category label (e.g. "Infantry", "Artillery")
unitsstring[]Array of DCS unit type strings to spawn
-- Example troop template
["JTAC_4man"] = {
    namePrefix  = "JTAC_Team",
    displayName = "JTAC 4-Man Team",
    category    = "JTAC",
    units = { "Soldier M4", "Soldier M4", "Soldier M4", "Soldier M249" }
},

-- Example vehicle template
["CHAP_M1126"] = {
    namePrefix  = "JTAC_Stryker",
    displayName = "M1126 Stryker ICV",
    category    = "APC",
    units = { "CHAP_M1126" }
},
Unit type strings must match DCS internal type names exactly. Check dcs.log for [DGSS_CTLD] Template not found warnings if spawns fail silently.

Config — CTLD Pickup Zones

Pickup zones are defined as trigger zones in the ME. Any trigger zone whose name matches your configured pattern is treated as a CTLD zone. Players must be inside a zone to load troops or vehicles. Zone names and allowed cargo types are set in the script config section near the top.

There's no zone name pattern filter by default — all zones shown in the F10 menu are available. Add zone name checks in DGSS_CTLD.getAvailableZones() if you want to restrict which zones offer which cargo.

Config — JTAC Targeting

SCAN_RADIUS10,000 mDetection radius each JTAC team searches for enemies.▼ details

Every JTAC team scans a 10 km circle around its position and collects all RED ground units. Results are sorted by distance. Lowering this forces players to position JTACs closer to the action; raising it allows long-range laser designation.

Targeting interval2 sHow frequently each JTAC re-evaluates its target and updates the laser spot.▼ details

The laser is destroyed and recreated every 2 seconds to track a moving target. The DCS Spot API requires the spot to be re-placed when the target moves. Both the laser spot and IR pointer are updated together.

Menu poll interval3 sHow frequently the JTAC Control sub-menu is rebuilt.▼ details

The menu only rebuilds when the JTAC team count changes (not every cycle). The poll detects count changes every 3 seconds. This means new JTACs appear in the menu within 3 seconds of deployment.

Status monitor interval60 sHow often dead teams are cleaned from the registry.▼ details

Dead JTAC groups are detected and removed from DGSS_CTLD.JTAC_REGISTRY every 60 seconds. Cleanup loop (full group audit) runs every 600 seconds.

JTAC scan loop15 sHow often each JTAC rescans for targets and issues new 9-line callouts.▼ details

The main JTAC scheduling loop (scheduleJtacLoop) runs every 15 seconds for each active JTAC. On each cycle, the JTAC collects all RED units within SCAN_RADIUS, performs line-of-sight checks, picks the best target (nearest visible or manual override), and updates the laser and CAS callout if the target changed.

Performance note (Feb 2026): Reduced from 8 s to 15 s. The previous interval also contained a double LOS raycast bug — land.isVisible() was called once inside a pcall() and then again outside it. This has been fixed; the LOS check now runs exactly once per target per cycle via pcall(land.isVisible, ...).

Menu builder interval15 sHow often the static JTAC menu tree is fully rebuilt.▼ details

The staticJtacMenuBuilder timer checks every 15 seconds whether the set of active JTACs has changed. If so, the F10 JTAC Control sub-menu is torn down and rebuilt from scratch to reflect current JTAC teams.

Performance note (Feb 2026): Reduced from 5 s to 15 s. Menu rebuilds are relatively expensive (they touch missionCommands), but the set of active JTACs changes infrequently in practice, so a 15-second poll is more than sufficient.

Config — Laser Codes

Each JTAC team is assigned a unique 4-digit laser code automatically from a pool. The code is announced in the 9-line callout message. Players must dial in the correct code on their targeting pod or LGB seeker.

Default laser code pool starts at 1111 and increments per team. To change the starting code or pool, find the DGSS_CTLD.LASER_CODES table or the code assignment in the JTAC spawn function.

CTLD — F10 Radio Menu Flow

  1. Fly to / hover over a CTLD pickup zone
  2. F10 → CTLD → Load Troops or Load Vehicle
  3. Select template from sub-menu
  4. Fly to deployment location
  5. F10 → CTLD → Deploy Troops / Deploy Vehicle
  6. Group spawns at aircraft position; squad is registered as a JTAC if eligible
Only one troop load and one vehicle can be carried at a time per aircraft. Loading a second payload overwrites the first (not stacked).

JTAC Control — F10 Radio Menu Flow

  1. F10 → JTAC Control → select a JTAC team by name
  2. Sub-menu shows: Status, Next Target, Previous Target, Auto Target (Nearest)
  3. Next / Previous Target — cycles through the available target list (sorted by distance). JTAC immediately re-lases the selected target.
  4. Auto Target — clears manual override; JTAC returns to tracking the nearest enemy automatically.
  5. Status — prints current target type, MGRS, laser code, and number of available targets.

On target change the JTAC broadcasts a CAS callout to BLUE coalition:

JTAC_Team_0001: MARKING NEW TARGET
Type: T-80
MGRS: 42S WB 12345 67890
Lat/Lon: 32°24'N 065°00'E
Distance: 3.4 NM
Laser Code: 1111

Mission Editor Setup Checklist

  1. Load script — MISSION START trigger → DO SCRIPT FILE → DGSS-CTLD-JTACv7.2.lua
  2. CTLD zones — place trigger zones where players can load troops/vehicles. Name them descriptively; the script lists available zones in menus based on player proximity.
  3. Templates — verify DCS unit type names in DGSS_CTLD.TROOP_TEMPLATES and DGSS_CTLD.VEHICLE_TEMPLATES match valid types for your country setting.
  4. Country setting — set DGSS_CTLD.COUNTRY to the desired coalition country. Default is country.id.USA. Mismatched country/unit type causes silent spawn failure.
  5. Enemy groups — ensure RED ground units are present in the area so JTACs have targets to detect.
