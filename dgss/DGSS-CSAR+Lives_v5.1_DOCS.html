DGSS CSAR + Lives System

DGSS-CSAR+Lives_v5.1.lua  ·  Crash / eject survivor rescue with per-player lives tracking and lockout

How It Works

Two tightly integrated systems run in one script:

CSAR
When a BLUE pilot crashes or ejects, a survivor unit spawns 150–200 m from the crash point, marked with blue smoke on request. Helicopter crews locate the survivor via F10 menu, hover low and slow to pick them up, then fly to a drop-off base. On delivery, the downed pilot's life count is restored.
Lives
Every BLUE player starts with 5 lives. Each death or crash deducts 1 life. When lives hit 0 the player is locked out of spawning for 10 minutes. Rescuing a survivor gives that player's count back to them (+1 per rescue, up to the max).
Anti-duplicate protection: A 30-second cooldown window prevents double-counting when an ejection and aircraft destruction happen within the same incident. A separate 5-minute eject exemption ensures players who eject are not penalised for leaving the ejected seat (SLOT_LEAVE event).

Config — Lives Settings

All lives settings live inside DGSS_CSAR.LIVES = { ... }.

enabledtrueMaster switch for the lives system. Set to false to run CSAR only.▼ details

When false, no life counts are tracked, no lockouts are applied, and functions like DGSS_CSAR.loseLife() and DGSS_CSAR.gainLife() return immediately. CSAR rescue still works.

defaultLives5How many lives a player starts with (first death event initialises them to this value).▼ details

Players are not initialised until their first death event fires. If you want all players initialised at mission start, call DGSS_CSAR.getPlayerLives(playerName) in a separate startup loop.

maxLives5Hard cap — lives can never exceed this value regardless of how many rescues a player performs.▼ details

Applies to DGSS_CSAR.gainLife(). The actual formula is math.min(maxLives, current + lifeGainAmount).

loseLifeOnDeathtrueDeduct a life when a player crashes or is killed.▼ details

Triggered by DCS S_EVENT_PILOT_DEAD and S_EVENT_CRASH events. The 30-second INCIDENT_COOLDOWN prevents double-counting across both events for the same incident.

gainLifeOnRescuetrueGive the rescued pilot's original player a life back when delivered to a drop-off base.▼ details

The script looks up the survivor's playerName stored at spawn time. If that player is currently in a slot, they receive an in-cockpit notification. Otherwise a coalition-wide message is broadcast.

lifeGainAmount1How many lives are restored per successful rescue delivery.▼ details

Increase to reward rescue more aggressively, but be aware that maxLives is still capped. Setting this to 2 or 3 lets skilled CSAR teams bank extra lives.

Config — Lockout

When a player's lives reach 0 they are locked out of spawning for a fixed duration.

Lockout duration600 s (10 min)Hard-coded in DGSS_CSAR.loseLife() — change now() + 600 to adjust.▼ details

When lives hit 0, a lockout expiry time is written to DGSS_CSAR.LOCKOUT[playerName]. On each spawn attempt the script compares the current mission time against this expiry. If time has not elapsed, spawn is blocked and the player sees the noLivesLeft message.

The in-game message currently reads: "You have no lives remaining. You will regain 1 life in 10 minutes." If you change the lockout duration remember to update this message string in DGSS_CSAR.MESSAGES.noLivesLeft.

INCIDENT_COOLDOWN30 sPrevents counting the same crash as multiple deaths (eject + explosion both fire events).▼ details

After the first death/eject event for a player, a 30-second window blocks further event processing for the same player. This covers the typical ejection → aircraft destruction → seat separation sequence. Tracked in DGSS_CSAR.INCIDENT_PROCESSED.

EJECT_EXEMPTION_TIME300 s (5 min)Players who eject are exempt from SLOT_LEAVE life penalty for this many seconds.▼ details

After ejecting, players must control a parachute/ejected seat. They will inevitably leave that slot. Without this exemption, leaving the seat would trigger a S_EVENT_PILOT_DEAD / slot leave event and incorrectly deduct another life. The 5-minute window provides ample time for the parachute sequence to complete. Tracked in DGSS_CSAR.EJECTED_PLAYERS.

Config — CSAR Settings

All CSAR settings live inside DGSS_CSAR.CSAR = { ... }.

enableAutoSpawnOnEjecttrueAutomatically spawn a survivor group when a pilot ejects or crashes.▼ details

Listens for S_EVENT_EJECTION and S_EVENT_CRASH. When triggered, DGSS_CSAR.spawnSurvivorGroup() is called with the crash position. The survivor spawns 150–200 m away at a random offset angle to separate it from burning wreckage.

pickupRadius75 mHow close a helicopter must be (horizontal) to a survivor to initiate a pickup.▼ details

Combined with the altitude check (pickupAltitudeMax). Both conditions must be met simultaneously. The radius is checked in 2D (X/Z plane only, ignoring vertical). Increase this if terrain makes it hard to get exactly overhead; decrease for tighter, more realistic hovering requirements.

pickupAltitudeMax50 m AGLMaximum altitude AGL at which a pickup can be initiated.▼ details

Altitude is measured using unit:getPoint().y - land.getHeight(pos) to get true AGL. This means hilly terrain is correctly accounted for. Note that the internal variable is stored as MAX_PICKUP_ALTITUDE = 15.2 m (50 ft) — that is the script default; verify the values are in sync if you edit one but not the other.

smokeOnRequesttruePlayers can request smoke from the survivor via the F10 menu.▼ details

Smoke colour is blue (trigger.smokeColor.Blue). Smoke is triggered at the survivor's current position. If the survivor moves (it is an immortal ground unit with no orders so it generally stays still), the smoke will still appear at the trigger point.

nearestSearchRadius148,160 m (80 NM)Maximum distance for the "Find Nearest Survivor" menu option.▼ details

Used in DGSS_CSAR.findNearestSurvivor(). The function iterates all entries in DGSS_CSAR.SURVIVORS and returns the closest one within this radius. 80 NM covers virtually the entire Afghanistan map.

despawnOnRescuetrueDestroy the survivor ground unit after successful drop-off.▼ details

Keeps the map tidy. The entry is also removed from DGSS_CSAR.SURVIVORS and the carrying aircraft's state is cleared from DGSS_CSAR.CARRYING_SURVIVOR. Set to false if you want the unit to persist on the map (e.g., for base defence immersion).

Config — Speed & Altitude Limits

These limits apply to both pickup and drop-off operations.

ParameterDefaultEquivalentApplies To
MAX_PICKUP_SPEED7.5 m/s~10 knotsPicking up a survivor
MAX_PICKUP_ALTITUDE15.2 m AGL~50 ftPicking up a survivor
MAX_DROPOFF_SPEED7.5 m/s~10 knotsDelivering at a drop-off zone
MAX_DROPOFF_ALTITUDE15.2 m AGL~50 ftDelivering at a drop-off zone
If a player exceeds these limits when they attempt pickup/drop-off, the operation fails and a message shows their exact current speed and altitude alongside the limit. They must slow down and descend before trying again.
Altitude is True AGL, computed as unit.getPoint().y - land.getHeight(pos). This is terrain-aware — flying 15 m above a hill counts as 15 m AGL even if the sea-level altitude is much higher.

CSAR Step-by-Step

1
Pilot crashes or ejects — S_EVENT_CRASH / S_EVENT_EJECTION fires. The script spawns an immortal soldier 150–200 m from the crash point and broadcasts a coalition-wide mayday.
2
CSAR crew locates the survivor — F10 → CSAR → Nearest Pilot or Nearest Convoy Survivor. A text callout provides MGRS, latitude/longitude (degrees + decimal minutes), distance, and bearing.
3
Request smoke (optional) — F10 → CSAR → Request Smoke on Survivor. Blue smoke deploys at the survivor's position.
4
Hover over the survivor — fly within 75 m horizontal, below 15.2 m AGL, and below 7.5 m/s. Then select F10 → CSAR → Pick Up Survivor. A countdown/confirmation message confirms loading.
5
Fly to a drop-off zone — any of the 13 zones listed above. Enter the trigger zone boundary.
6
Land and drop off — hover below 15.2 m AGL at under 7.5 m/s inside the zone, then F10 → CSAR → Drop Off Survivor. Rescue completes: the survivor despawns, the downed pilot gains +1 life, the rescuing crew earn leaderboard points (if leaderboard script is loaded).
Carrying state is per-aircraft. If the rescue helicopter is destroyed while carrying a survivor, the survivor is lost and no rescue credit is given. There is currently no "survivor overboard" re-spawn on carrier destruction.

Lives System — Player Flow

1
Player spawns for the first time — initialised to defaultLives = 5. No notification.
2
Player dies / crashes — DGSS_CSAR.loseLife() is called. Lives −1. In-cockpit HUD message shows remaining count. 30-second cooldown starts to block duplicate events from the same incident.
3
Lives reach 0 — lockout timer starts (10 minutes). Message: "You have no lives remaining. You will regain 1 life in 10 minutes." Spawn attempts are blocked until the timer expires.
4
Player is rescued — DGSS_CSAR.gainLife(playerName) fires. Their count goes up by lifeGainAmount = 1. They receive a notification wherever they currently are. If they currently have 0 lives and the lockout hasn't expired, gaining a life does NOT cancel the lockout — they must wait out the timer.
5
Ejection path — eject event fires → life deducted → 5-minute eject exemption window opens. Player controls parachute/seat → leaves that slot → SLOT_LEAVE event fires → exemption check passes → no additional life deducted.

Mission Editor Checklist

  1. Load script — MISSION START trigger → DO SCRIPT FILE → DGSS-CSAR+Lives_v5.1.lua
  2. Drop-off zones — for each name in DGSS_CSAR.CSAR.dropOffZones, place a trigger zone in the ME with an exactly matching name. Zone size determines how easy it is to land inside — 500–1000 m radius recommended for airfields.
  3. Coalition settings — DGSS_CSAR.COALITION defaults to coalition.side.BLUE. Change if you want a RED-side CSAR system.
  4. Country setting — DGSS_CSAR.COUNTRY defaults to country.id.USA. Survivor ground units use this; must be a valid country for Soldier M4.
  5. Aircraft whitelist — add any custom mod helicopters or aircraft to DGSS_CSAR.ALLOWED_UNITS before mission start.
  6. Tune lives — adjust defaultLives, maxLives, and the lockout duration in DGSS_CSAR.loseLife() to match your server's difficulty.

Troubleshooting

SymptomCause & Fix
No survivor spawned after crashenableAutoSpawnOnEject may be false, or the crash was not a BLUE player event. Check dcs.log for [CSAR] event lines.
"Speed too high" even when hoveringBlade stall or autorotation giving residual velocity. Wait a moment after collective reduction; the speed check uses real-time m/s.
"Altitude too high" at what looks like ground levelTerrain slope — the AGL check is accurate to the local ground cell. Move slightly to flatter ground and retry.
Pickup fails — "No survivors nearby"You are more than 75 m from the survivor horizontally. Use the "Nearest" menu to check distance.
Life count didn't go up after rescuegainLifeOnRescue is true but check the drop-off zone name matches exactly (case-sensitive) a trigger zone in the ME.
Lives deducted twice for one crashNormally prevented by the 30-second cooldown. If still happening, check INCIDENT_COOLDOWN value; a very long explosion chain may require a higher value.
Player locked out but shouldn't beVerify the player's name matches exactly — DGSS_CSAR.PLAYER_LIVES is keyed by exact name string. Name changes between sessions will create a new entry.
