DGSS IED System — Road Placement

DGSS-IED_System 6.2_RoadPlacement.lua  ·  Places IEDs along road networks between bases with async pathfinding, insurgent ambushes & 24/7 server support

How It Works

The IED system uses DCS's land.findPathOnRoads() API to discover road networks between base pairs. It samples positions along each route, validates them against _IED_AREA trigger zones, enforces minimum spacing (2 km), and spawns prop objects (oil barrel + vehicle) at each position. When a BLUE convoy vehicle enters the trigger radius, the IED detonates after a random vehicle count threshold (1–8).

Configuration — General

COALITIONBLUECoalition whose vehicles trigger IEDs.▼ details

Only ground units from this coalition are checked against IED trigger radii. Change to coalition.side.RED to flip the scenario.

CHECK_INTERVAL10 sHow often active IEDs are checked for nearby vehicles.▼ details

Every 10 seconds checkActiveIEDs() iterates all BLUE ground groups and checks each against all non-exploded IEDs. A spatial pre-filter (Manhattan distance <200) skips distant groups. At 10 convoys a scan has ~150 checks — negligible CPU.

MAX_ACTIVE_IEDS75Maximum total IEDs on the map at any time.▼ details

Caps the total number of non-exploded IEDs. If the limit is reached, no new IEDs are placed until existing ones detonate and reset. The round-robin distributor ensures fair allocation across all base pairs before the cap is hit.

RESET_TIME1800 s (30 min)Time before an exploded IED respawns new props at the same location.▼ details

After detonation, a timer.scheduleFunction re-arms the IED at 30 minutes. The same position is reused with a new random trigger count (1–8 vehicles). Designed for 24/7 server operation where convoys repeat routes.

DETECTION_RADIUS15 mExtra buffer added to the 50 m core trigger radius.▼ details

Total trigger radius is 50 + DETECTION_RADIUS = 65 m. Units within this circle around the IED props are counted. Increase for wider roads; decrease for precision placement.

CLEANUP_INTERVAL3600 s (1 hr)Maintenance cleanup cycle for long-running servers.▼ details

performMaintenance() cleans dead insurgent group references, invalid static-to-IED mappings, oversized position tables, and orphaned reset timers. Logs memory stats after each run.

Route Mode (Default)

When USE_ROUTE_MODE = true, the system:

  1. Builds a pathfinding queue for all base pairs × routesPerBasePair routes.
  2. Processes one pathfind per pathfindDelay (1.5 s) to avoid frame spikes.
  3. Caches results in ROUTE_CACHE. Route 1 is direct; routes 2+ use intermediate waypoints offset perpendicular to the direct line at 25%–75% along the path.
  4. After all routes are cached, activateIEDsOnRoutes() samples candidate positions, validates them against _IED_AREA zones and exclusion zones, checks min spacing, then distributes IEDs in a round-robin across base pairs until MAX_ACTIVE_IEDS is reached.
Priority routes: KABUL ↔ BAGRAM ↔ JALALABAD are processed first to ensure the most active convoy corridor gets IEDs before the cap fills.

Zone Mode (Legacy)

When USE_ROUTE_MODE = false, IEDs are placed within individual _IED_AREA zones by sampling random points and finding road paths back to the zone centre. Zones are activated one per ZONE_SPAWN_DELAY (15 s). Limited to iedsPerZone per zone.

Async Pathfinding

The processPathfindQueue() function processes one pathfinding request per frame interval (1.5 s). Each request calls land.findPathOnRoads("roads", fromX, fromZ, toX, toZ) and caches the result. Progress is logged as a percentage. When the queue is empty, activateIEDsOnRoutes() is called to place IEDs from the cached routes.

For alternate routes (routeNum ≥ 2), an intermediate waypoint is constructed perpendicular to the direct line between bases. The path is built in two segments (base A → waypoint → base B) to discover different road networks.

IED Lifecycle

  1. Placement — Props spawned: Oil Barrel (hidden static) + random vehicle (P20_drivable or VAZ Car), offset 8–15 m from road.
  2. Detection — Every 10 s, BLUE ground units within 65 m are counted. Each unique unit increments vehiclesSeen.
  3. Detonation — When vehiclesSeen ≥ triggerCount (random 1–8), or if an IED prop is destroyed by fire/bombing: explosion (500 kg TNT) + smoke + flares + MGRS text message.
  4. Insurgent ambush — 40% chance of 10–15 infantry spawning 100–300 m away.
  5. Reset — After 30 minutes, props respawn at the same location with a new random trigger count.

Maintenance (24/7 Support)

performMaintenance() runs every hour and cleans:

  • Dead insurgent group references
  • Invalid static-to-IED mappings
  • Oversized IED_POSITIONS table (trimmed to MAX_TRACKED_POSITIONS = 500)
  • Orphaned reset timers for deleted IEDs

Memory stats (active, exploded, groups, mappings, positions, timers) are logged after each run.

Mission Editor Checklist

  1. Load script — MISSION START → DO SCRIPT FILE → DGSS-IED_System 6.2_RoadPlacement.lua.
  2. IED area zones — Place trigger zones containing _IED_AREA in their name. IEDs are only placed at road positions inside these zones.
  3. Base exclusion zones — Ensure all entries in BASE_EXCLUSION_ZONES exist as trigger zones in the ME (KANDAHAR, BAGRAM, etc.). IEDs won't spawn inside them, and they serve as route endpoints.
  4. Road network — The DCS map must have road data. Syria, Caucasus, and Persian Gulf all have adequate road networks. The script uses land.findPathOnRoads("roads", ...).
  5. BLUE convoys — Place or spawn BLUE ground groups that traverse the road network. The IED system detects any BLUE ground unit, not just convoy-specific groups.
