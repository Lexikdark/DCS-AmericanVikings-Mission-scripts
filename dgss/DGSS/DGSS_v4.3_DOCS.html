DGSS v4.3 — Dynamic Insurgent Zone Spawner

DGSS_v4.3.lua  ·  Polygon-safe insurgent spawning with global shuffle bag, scripted ground engagements, and F10 map markers

How It Works

The script monitors 18 named trigger zones. Every 5 minutes it counts live groups per zone and compares against each zone's configured min/max. If a zone is below its minimum, new groups spawn immediately. If between min and max, a random number of extra groups may spawn. When a group is killed, the slot opens and the system refills it in the next cycle.

Normal insurgent spawn
A template is drawn from the global shuffle bag and spawned via mist.dynAdd anywhere inside the zone (polygon-safe). Units use country.id.CJTF_RED, skill = Random. A F10 map marker is placed at the spawn point immediately. Smoke can optionally be enabled (off by default).
Engagement spawn
Six templates have isEngagement = true. These spawn two opposing groups 200–500 m apart, facing each other. The RED group uses CJTF_RED; the BLUE group uses country.id.USA. Both are ordered to AttackGroup the other. When the RED group is eliminated (or the engagement times out) both groups are destroyed and a re-spawn is triggered after 5 seconds.

Config — General

MAX_CONCURRENT_ENGAGEMENTS15Maximum number of active scripted ground engagements at any time.▼ details

When an engagement template is drawn and this limit is already reached, the spawn is skipped entirely rather than queued. The zone count still ticks down, meaning the zone may be refilled with a normal template on the next attempt. Lower this on performance-sensitive servers (each engagement has two actively fighting groups).

ENGAGEMENT_TIMEOUT1200 s (20 min)Maximum time an engagement can run before it is forcibly ended.▼ details

Prevents engagements from running indefinitely when units get stuck, retreat behind terrain, or fail to spot each other. On timeout, both groups are destroyed, the engagement slot is freed, and a re-spawn is triggered in 5 seconds.

MAX_SPAWNS_PER_CYCLE3Rate-limits how many groups can spawn in a single checkZones() pass.▼ details

Prevents a burst of mist.dynAdd calls when many zones are below minimum at the same time (e.g. after a large wipe). Remaining zones are filled in the next cycle (5 minutes later). Increase if you need faster refill after server restart.

ENABLE_SMOKEfalsePlace an orange smoke marker at each spawn point.▼ details

Set to true to enable. Smoke colour is orange (SMOKE_COLOR = 1) to avoid confusion with CSAR blue smoke. This is a purely visual cue for mission design testing — disable for live server use as it marks every spawn for ALL players.

Min vs Max behaviour:
  • Below min → spawn exactly enough groups to reach minimum (up to the cycle rate limit).
  • Between min and max → spawn a random number between 1 and max - count extra groups.
  • At max → nothing spawns.
  • Min = 0 → zone is optional; no guaranteed state but the max cap still applies.
To add or remove a zone: update both the zones array and the zoneSettings table. Place (or remove) the matching trigger zone in the ME. Zone type can be polygon or circular — polygon zones use mist.getRandPointInPolygon; circular zones get a uniform random point inside the radius.

Shuffle Bag System

All 20 templates are managed through a global shuffle bag — a randomised queue that guarantees every template appears exactly once before any template repeats.

-- Fisher-Yates shuffle fills the bag from all 20 templates
local function shuffleTemplates()
    shuffleBag = {}
    for i = 1, #INSURGENT_TEMPLATES do
        shuffleBag[i] = INSURGENT_TEMPLATES[i]
    end
    for i = #shuffleBag, 2, -1 do
        local j = math.random(1, i)
        shuffleBag[i], shuffleBag[j] = shuffleBag[j], shuffleBag[i]
    end
end

local function getNextTemplate()
    if #shuffleBag == 0 then shuffleTemplates() end  -- auto-refill when exhausted
    return table.remove(shuffleBag)
end
Why a shuffle bag instead of pure random? Pure random can produce streaks (e.g. 5 T-55 armour groups back to back). The shuffle bag guarantees variety — if you see Ins_20 (two Grad-URALs) early in a session, you won't see it again until all other 19 templates have been drawn. The bag refills automatically and reshuffles when empty.

Spawn Logic

Every spawn attempt makes up to 5 tries before giving up. Each attempt:

  1. Fetch a zone reference via trigger.misc.getZone(zoneName).
  2. Get a random point inside the zone — mist.getRandPointInPolygon() for polygon zones, uniform-radius random for circular zones.
  3. Draw the next template from the shuffle bag.
  4. If it is an engagement template, check MAX_CONCURRENT_ENGAGEMENTS — skip if at limit.
  5. Build the unit table with positions offset by each unit's dx/dy.
  6. Call mist.dynAdd(groupTemplate).
  7. Verify the returned group name exists via Group.getByName and has live units. If not, log a warning and retry.
  8. On success: register in activeGroups, place F10 marker, optionally place smoke.
If all 5 attempts fail (e.g. zone has bad geometry, MIST polygon point returns nil repeatedly) the spawn logs an error and exits. The zone will be re-checked on the next 5-minute cycle.

Engagement System

The cleanupGroups() function handles engagement lifecycle every 2 minutes:

ConditionAction
RED group deadDestroy BLUE group → remove both from tracking → schedule re-spawn in 5 s
Engagement > 20 min oldDestroy both groups → remove from tracking → schedule re-spawn in 5 s
BLUE dead but RED aliveDestroy both groups → remove from tracking → no re-spawn (insurgents "won")
Either group no longer existsRemove from tracking → no re-spawn (group was externally destroyed)
Re-spawn after a completed engagement uses the same zone name the original pair occupied. If MAX_CONCURRENT_ENGAGEMENTS is already full at re-spawn time, the re-spawn is skipped and the zone remains empty until the next regular cycle.

F10 Markers & Smoke

Every spawned group (normal or engagement — RED side only) gets an F10 map marker placed immediately at its spawn point via trigger.action.markToAll.

  • Marker text: "Enemy Forces"
  • Visible to all coalitions (public marker)
  • Marker ID stored in markerManager.active[groupName]
  • Auto-removed when markerManagerCleanup() detects the group is dead (runs every 2 minutes)
  • If a group name re-uses a marker slot (shouldn't happen with timestamp-based names), the old marker is removed first

Smoke is disabled by default (ENABLE_SMOKE = false). When enabled, orange smoke triggers at the Vec3 ground position of the spawn point.

Cleanup & Memory Management

Three cleanup mechanisms run at different intervals:

FunctionIntervalWhat It Does
cleanupGroups()Called inside cleanupLoop() every 2 min + inside checkZones() every 5 minIterates activeGroups and engagementGroups; removes entries for dead groups; handles engagement lifecycle (see above)
markerManagerCleanup()Called inside cleanupLoop() every 2 minRemoves F10 markers for dead groups via trigger.action.removeMark
performMemoryCleanup()Every 20 min (via mist.scheduleFunction)Deep-audits both tracking tables for nil or non-existent group references; logs removed count; does NOT remove physical wreckage (left to DCS)
Physical wreckage is intentionally left in place — the script only clears its own Lua references. DCS handles wreckage lifespan natively. This avoids Group.destroy() errors on already-dead groups.

Mission Editor Checklist

  1. Load MIST first — MISSION START trigger → DO SCRIPT FILE → mist.lua.
  2. Load script — MISSION START trigger → DO SCRIPT FILE → DGSS_v4.3.lua (after MIST).
  3. Place trigger zones — create 18 zones named exactly ZONE1 through ZONE18. Polygon zones are preferred for irregular terrain; circular zones work but spawn points are radius-uniform (not edge-weighted).
  4. Size zones appropriately — zones that are too small (under ~200 m radius) can cause polygon-point failures or tight clustering of spawns. 500 m–2 km radius zones work best.
  5. Avoid overlapping zones with friendly airbases — units spawn with ground task "Nothing" so they will not automatically move, but spawning inside a friendly base perimeter is visually inconsistent.
  6. Adjust min/max per zone — edit zoneSettings at the top of the script to match the operational weight of each zone in your mission design. Frontline zones get higher min; rear-area zones get min=0.
  7. Check unit type validity — all units in templates use country.id.CJTF_RED (RED side) or country.id.USA (BLUE side engagement groups). Verify the DCS unit types are valid for those countries in your DCS version.
