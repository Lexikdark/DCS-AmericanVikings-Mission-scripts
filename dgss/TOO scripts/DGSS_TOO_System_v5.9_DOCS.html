DGSS Target of Opportunity System

DGSS_TOO_System v5.9.lua  ·  Spawns 30 rotating insurgent target templates across 60 zones with 9-line CAS briefs, F10 menu & auto-maintenance

How It Works

The TOO system maintains a minimum of 8 active insurgent targets on the map at all times. Each target is a combination of static buildings (tents, structures) and a ground unit group (infantry, technicals, AA). Templates are rotated sequentially (1–30) and placed randomly within one of 60 TOOZONE trigger zones. Players access targets via F10 radio menu with slot-based dynamic mapping.

Configuration — General

TOO_CONFIG.minTargetsOnMap8Minimum active targets maintained on the map at all times.▼ details

The maintenance loop checks every 60 seconds and spawns new targets until this count is reached. If all 60 zones are occupied (which can't happen at 8 targets), no more are spawned.

TOO_CONFIG.maxAttempts12Maximum spawn retries per target if initial position fails.▼ details

Each spawnTargetOfOpportunity() call tries up to 5 positions (inner retry). If the group fails to spawn (no valid position in zone), the maintenance loop retries up to maxAttempts total.

maintenanceCheckInterval1800 s (config) / 60 s (actual)How often dead targets are cleaned and new ones spawned.▼ details

The config value is 1800 s (30 min) but the actual scheduler runs maintenanceCheck() every 60 seconds. This ensures fast respawns. The config value is defined but not directly used — the 60 s timer overrides it.

Configuration — Spawn Zones

60 trigger zones named TOOZONE1 through TOOZONE60. Each zone is a circular trigger zone in the ME. The script picks random unoccupied zones for each new target.

Place zones in areas with interesting terrain for CAS practice. Avoid placing zones on water, steep mountains, or inside friendly base perimeters. The larger the zone radius, the more variety in target placement within that zone.

Configuration — Templates

30 templates defined in TOO_TEMPLATES, cycled sequentially. Each template has:

FieldDescription
nameTemplate identifier (e.g. Taliban_Kandahar_Cell)
buildingsArray of static objects: {type, offset={x,y}}. Types: WC, Tent04, Tent05, Building07_PBR, Building08_PBR
unitsArray of ground units: {type, offset={x,y}}. Types include infantry (AK, RPG, Stinger), technicals (P20, HL_DSHK, tt_ZU-23), artillery (Grad-URAL, 2B11 mortar), light AA (HQ-7), vehicles (LAZ Bus, Ural)

Templates range from 9–18 units and 1–5 buildings each, with offsets spread across a ~160 m square area.

Spawn Flow

  1. Pick next template in sequence (cycles 1–30).
  2. Select a random unoccupied zone from TOO_ZONES.
  3. Generate random position within zone radius (uniform circle distribution).
  4. Spawn static buildings via mist.dynAddStatic (country: CJTF_RED, category: Fortifications).
  5. Spawn unit group via mist.dynAdd (country: CJTF_RED, category: vehicle, task: "Ground Nothing").
  6. Verify group exists and has live units.
  7. Register in activeTargets, mark zone as occupied, place map marker at first unit position.

Maintenance Loop (60 s)

Every 60 seconds maintenanceCheck() runs:

  • cleanupDeadTargets() — removes dead groups, frees zones, destroys orphaned statics via mist.removeStatic.
  • markerManagerCleanup() — removes map markers for dead groups.
  • cleanupPlayerMenus() — clears menu tracking for disconnected players.
  • updateDestroyedBuildings() — counts destroyed statics per group via Object.getByName.
  • Re-applies markers to living groups missing one.
  • Spawns new targets until minTargetsOnMap = 8 is reached.

Map Markers

Each active target gets a map marker prefixed [TOO] with the template name and grid reference. Markers are placed at the first unit's actual position (not zone centre). The markerManager tracks marker IDs and cleans up on target death.

9-Line CAS Brief

Generated on demand via F10 menu. Format:

1. IP:        GRID <ipGrid>
2. HEADING:   <bearing> degrees
3. DISTANCE:  On Grid <ipGrid> - X.X km from center
4. ELEVATION: <meters>
5. TARGET:    <type> (<count> units)
6. LOCATION:  <MGRS> / <DD°MM'SS">
7. MARK:      VISUAL ONLY
8. FRIENDLIES: CLEAR
9. REMARKS:   <displayName>

Bearing and distance are calculated from the grid centre to give pilots an ingress reference.

F10 Radio Menu

Each BLUE player group gets a Mission Targets sub-menu:

CommandDescription
List Active TargetsShows total count and all active target names.
Target 1 – 8Slot-based sub-menus that dynamically map to living targets.

Each target slot has:

  • 9-Line Brief — Full 9-line CAS callout (displayed 30 s).
  • Target Status — Shows alive/killed unit count and intact/destroyed building count.
  • What Target Is This? — Template name, total units, grid reference.
Slots are dynamic — Target 1 always maps to the first living target, regardless of spawn order. No menu rebuild is needed when targets die.

Mission Editor Checklist

  1. MIST — MISSION START → DO SCRIPT FILE → mist_4_5_126.lua.
  2. Load script — MISSION START → DO SCRIPT FILE → DGSS_TOO_System v5.9.lua.
  3. 60 trigger zones — Place circular trigger zones named TOOZONE1 through TOOZONE60. Radius should be 2–10 km for variety.
  4. Country availability — Ensure CJTF_RED (or the configured country) is available in the mission. Units spawn as this country.
  5. Terrain check — Avoid placing zones entirely over water. The script does not have a water check — if a random position in a zone is over water, the spawn will fail and retry.
