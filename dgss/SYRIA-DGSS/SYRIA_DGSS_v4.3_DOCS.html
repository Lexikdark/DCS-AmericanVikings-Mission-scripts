SYRIA_DGSS v4.3

Dynamic Ground-Forces Zone Spawner — Syria Theatre / Syrian Arab Army composition
DCS World Red Coalition MIST Required 18 Zones · 20 Templates

What It Does

DGSS (Dynamic Ground-Forces Spawner System) automatically populates up to 18 named trigger zones with Syrian Arab Army ground-force groups. Groups are drawn from a pool of 20 pre-defined templates, shuffled randomly using a Fisher-Yates bag so every template fires before any repeats. When a group is destroyed, the zone repopulates on the next spawn cycle.

  • Groups spawn as Red / CJTF_RED coalition using mist.dynAdd.
  • Each spawned group receives an "Enemy Forces" map marker visible to all players — the marker auto-removes when the group is destroyed.
  • Five dedicated RED_SAM_SHORAD_ templates add radar-guided and IR SHORAD threats to the pool, tagged so IADS scripts (e.g. Skynet) can detect and manage them.
  • A rate limiter caps spawns at 3 per check cycle to avoid server performance spikes.
  • A memory-cleanup routine runs every 20 minutes to purge dead group references.
Syria Theatre All unit types in this file are Russian-origin vehicles operated by the Syrian Arab Army and are valid for the DCS Syria map without any mod dependencies.

Requirements

MIST (Mission Scripting Tools)

DGSS uses mist.dynAdd and mist.getRandPointInPolygon. MIST must be loaded before this script via a Mission Start trigger. Download: github.com/mrSkortch/MissionScriptingTools

DCS World Trigger Zones

Each zone listed in the zones table (ZONE1–ZONE18) must exist as a named trigger zone in the Mission Editor. Both circular and polygon zone types are supported.

Quick Start

1 — Load MIST first

In the Mission Editor, add a Mission Start trigger with a Do Script File action pointing to mist_4_5_126.lua (or your current MIST version).

2 — Load DGSS

Add a second Mission Start trigger (after MIST) with a Do Script File action pointing to SYRIA_DGSS_v4.3.lua.

3 — Create your zones

In the Mission Editor, create trigger zones named exactly ZONE1, ZONE2 … ZONE18. The script will log an error in DCS.log for any zone name it cannot find.

4 — Done

When the mission starts, DGSS logs === [DEBUG] Dynamic Insurgent Zone Spawner LOADED === and begins populating zones immediately. No further player interaction is needed.

Load Order Matters MIST must finish loading before DGSS. If both are on the same trigger, add a 1-second time delay condition to the DGSS action, or use a second trigger set to Once at mission time > 1 second.

Zone Setup

The spawn zone list is defined near the top of the script: 

local zones = {"ZONE1","ZONE2", ... ,"ZONE18"}

Adding a new zone

  1. Create the trigger zone in the Mission Editor with your chosen name (e.g. ZONE19).
  2. Add the name to the zones table.
  3. Add a corresponding entry in zoneSettings (see below).

Removing a zone

Delete its entry from both the zones table and the zoneSettings table.

Name must match exactly Zone names are case-sensitive. ZONE1 ≠ Zone1. If a zone name in the script does not exist in the mission, DGSS will log an error and skip that zone gracefully — it won't crash.

Zone Settings — min / max Spawn Counts

Each zone has its own min and max group count. The spawner enforces these on every check cycle (every 5 minutes):

  • min — if live group count drops below this, spawn immediately to refill.
  • max — hard cap; if count is between min and max, randomly spawn 1 to (max−count) groups.
  • Setting min = 0 means the zone can be empty between cycles.
local zoneSettings = {
    ZONE1  = { min = 2, max = 3 },
    ZONE10 = { min = 2, max = 7 },  -- busiest zone
    ZONE11 = { min = 0, max = 2 },  -- optional zone, can be empty
}

Visual Options

local ENABLE_SMOKE = false   -- set to true to drop a smoke marker at each spawn point
local SMOKE_COLOR  = 1        -- 0=Green 1=Orange 2=Blue 3=Red 4=White

Smoke is disabled by default to avoid confusion with CSAR blue smoke signals. You can enable it for testing to visually confirm that spawns are landing inside your zones. Orange (1) is recommended to avoid conflict with the CSAR system.

Rate Limiting

local MAX_SPAWNS_PER_CYCLE = 3  -- max groups spawned per 5-minute check cycle

This cap prevents the server from being hit with many simultaneous mist.dynAdd calls. If more zones need refilling than the cap allows, the remainder will be handled on the next cycle (5 minutes later). Increase this value on dedicated servers with spare CPU headroom; decrease it for MP sessions with many players.

Template Overview

The INSURGENT_TEMPLATES table holds 20 group definitions. Each template defines a name and a list of units with relative offsets (dx, dy in metres from the spawn anchor) and an initial heading in radians. 

{
    name = "Ins_1",
    units = {
        { type="T-72B",  dx=0.0,  dy=0.0,   heading=0.0 },
        { type="BMP-2",  dx=28.0, dy=-14.0, heading=0.3 },
        -- ...
    }
}
  • dx / dy — offset in metres from the random spawn point. Positive dy = north, positive dx = east (approximately).
  • heading — initial facing in radians (0 = North, π/2 ≈ 1.57 = East, π ≈ 3.14 = South).
  • All groups are spawned as Red / CJTF_RED with task Ground Nothing and skill random.

SHORAD Groups — Naming Convention

Any template with the RED_SAM_SHORAD_ name prefix is a dedicated short-range air-defence group. The prefix exists so that external IADS management scripts (such as Skynet-IADS) can identify and activate these groups as part of the integrated air-defence network.

Skynet / IADS Integration Skynet searches for groups by name prefix. Adding RED_SAM_SHORAD_ dynamically-spawned groups to Skynet requires Skynet's late activation or dynamic add API — check the Skynet docs for addSAMSite() calls if you want these groups to be networked.

Editing Existing Templates

Change a unit type

Find the template entry and update the type string to any valid DCS unit type name. Unit type names are case-sensitive and must match the DCS internal name exactly.

-- Replace a T-55 with a T-72B3:
{ type="T-72B3", dx=0.0, dy=0.0, heading=0.0 },

Adjust unit spacing

Increase dx/dy values to spread units further apart. Values are in metres. Typical vehicle spacing: 20–40 m. Keep formations compact enough to fit within your smallest trigger zone.

Change group skill

All groups currently use skill = "random". To set a fixed skill level, locate the spawn section in spawnGroupInZone and change the skill field:

skill = "random",   -- options: "Average", "Good", "High", "Excellent", "random"

Rename a template

Change the name field. To add the SHORAD prefix, rename to RED_SAM_SHORAD_Ins_X. The name affects the spawned group's DCS name (it becomes name .. "_" .. timestamp).

Adding New Templates

Add a new entry to the INSURGENT_TEMPLATES table, following the existing format. Place it before the closing } of the table. No other changes are needed — the shuffle bag auto-sizes to any number of templates.

-- Example: new T-80 heavy armour group
{
    name = "Ins_21",
    units = {
        { type="T-80UD",            dx=0.0,   dy=0.0,   heading=0.0 },
        { type="T-80UD",            dx=34.0,  dy=-20.0, heading=0.2 },
        { type="BMP-2",             dx=-28.0, dy=16.0,  heading=0.6 },
        { type="Infantry AK Ins",   dx=10.0,  dy=30.0,  heading=0.0 },
    }
},
Comma after the closing brace Every entry in the table except the very last must end with a comma after the }.

Shuffle Bag System

Instead of pure random selection (which can repeat the same template many times in a row), DGSS uses a Fisher-Yates shuffle bag:

  1. All 20 templates are copied into a bag and shuffled randomly.
  2. Each spawn draws from the bag (removing the entry).
  3. When the bag is empty, it is refilled and reshuffled.

This guarantees that every template is used exactly once before any template repeats, giving players varied and balanced encounters across a session.

Map Markers

When a group spawns, a map marker labelled "Enemy Forces" is placed at the spawn point, visible to all coalitions. The marker is automatically removed when the group is detected as dead by the 2-minute cleanup loop.

Marker IDs Marker IDs are randomly generated (10000–99999). The marker manager stores them by group name and never creates duplicates for the same group. All marker events are logged with the prefix [DGSS][MARKER].

Cleanup System

Three separate cleanup passes keep memory tidy during long missions:

cleanupGroups() — every 2 minutes

Scans activeGroups table; removes entries for any group where all units are dead or the group no longer exists in DCS.

markerManagerCleanup() — every 2 minutes

Removes map markers whose group has been cleaned up. Keeps the F10 map free of stale "Enemy Forces" icons.

performMemoryCleanup() — every 20 minutes

Full deep-clean pass over activeGroups. Logs the number of dead references removed. Physical wreckage is left for DCS to handle naturally.

Crash-safe design All cleanup functions use nil-safe guards (if g and g:isExist()) so they cannot error if DCS already garbage-collected a group object.

Spawn Logic — spawnGroupInZone()

The spawn sequence for a single group:

  1. Fetch the trigger zone via trigger.misc.getZone(). Log and abort if not found.
  2. Generate a random point inside the zone — uses mist.getRandPointInPolygon for polygon zones, or radius math for circular zones.
  3. Draw the next template from the shuffle bag.
  4. Build a unit list by offsetting each unit entry from the random anchor point.
  5. Call mist.dynAdd() with country = CJTF_RED. Up to 5 attempts if dynAdd fails.
  6. Verify the created group has at least one live unit.
  7. Register it in activeGroups and place an "Enemy Forces" marker.

Troubleshooting

Groups not spawning

  • Check dcs.log for [DGSS][ERROR] Zone not found: ZONEX — zone name mismatch between the script and the Mission Editor.
  • Ensure MIST is loaded before DGSS. Check load order in your triggers.
  • Verify the zone actually exists in the mission file — search for the zone name in the ME Trigger Zones panel.

dynAdd keeps failing (5 retries logged)

  • The random spawn point may be landing on impassable terrain (cliffs, water, buildings). Use a polygon zone that matches driveable terrain, or reduce the zone radius to avoid problem areas.
  • If this is a recurring zone, reduce max to lower the density.

Too many groups / performance issues

  • Reduce max values in zoneSettings for high-activity zones (especially ZONE10 which can hit 7 groups).
  • Reduce MAX_SPAWNS_PER_CYCLE (default 3) to spread spawns across more cycles.

Markers not clearing after kill

  • The marker cleanup runs every 2 minutes. Wait for the next cycle. If markers persist longer, check that isGroupDead() can see the group — sometimes groups with zero units but still technically existing in DCS need the 20-minute memory cleanup to fully clear.

SHORAD groups not detected by Skynet

  • Skynet requires groups to be added to its network at spawn time. Use Skynet's addSAMSite() API call inside a MIST:addEventHandler("birth", ...) or schedule a check after each spawn cycle to register new RED_SAM_SHORAD_ groups.

Reading the log

All DGSS messages are prefixed with [DGSS]. Filter your DCS.log with that string to see only relevant output:

[DGSS] Spawned group Ins_1_3845 in zone ZONE3
[DGSS][MARKER] Placed marker ID 47291 for Ins_1_3845
[DGSS] Cleaned up dead group Ins_1_3845
[DGSS][MARKER] Auto-removed marker for dead group Ins_1_3845
