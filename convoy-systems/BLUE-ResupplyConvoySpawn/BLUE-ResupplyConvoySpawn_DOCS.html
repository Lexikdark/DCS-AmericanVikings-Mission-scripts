BLUE-ResupplyConvoySpawn

v5.7.0 BLUE Coalition MIST Required Afghanistan Theatre · 2336 lines · Namespace: ConvoySystem

Overview

A fully automated logistics system that lets BLUE coalition players dispatch ground resupply convoys between 12 bases in the Afghanistan theatre via the F10 radio menu. Each convoy selects from one of five vehicle templates, travels a dynamically generated road route, and on arrival tops up the destination airbase's DCS warehouse with munitions and aircraft.

Convoys are tracked in real time: 2-minute progress broadcasts, stuck-detection with automatic re-routing, a 5.5-hour hard timeout, and integration with the DGSS_LEADERBOARD module for scoring.

Key facts at a glance
Max simultaneous convoys: 10  |  Per-template cooldown: 30 min  |  Update cycle: 5 min  |  Progress broadcast: every 2 min  |  Timeout: 5.5 h

Spawn Flow

1
Menu trigger

Player selects Template → Origin → Destination from the F10 menu. System checks: active convoy count < 10 AND selected template not on cooldown.

2
SpawnConvoyGroup()

Resolves ZONENAME_Spawn for the spawn position (random offset within 70 % of zone radius) and destination zone centre position.

3
Build unit array

All vehicles are placed in a two-column staggered formation (8 m longitudinal spacing, 8 m column separation) facing the heading toward the destination.

4
Route generation

A weighted dice roll selects Short / Medium / Long route (see Route Generation section). The full waypoint array is embedded directly into the spawn data.

5
Spawn via MIST or coalition.addGroup

Tries mist.dynAdd() first. Falls back to coalition.addGroup(country.id.USA, Group.Category.GROUND, ...) if MIST is unavailable.

6
AI options (3 s delayed)

After 3 seconds: sets Alarm State = GREEN, ROE = Return Fire, Disperse On Attack = true, Engage Air Weapons = false.

7
Register in tracking table

Convoy is stored in ConvoySystem.spawnedConvoys[convoyId] with status "traveling". Template cooldown timestamp is written to ConvoySystem.templateCooldowns[templateIndex].

8
On arrival (5-min update cycle detects arrival)

Convoy is marked "resupplying", performWarehouseResupply() is called once, leaderboard hook fires, group is despawned after 10 seconds.

Route Generation

All waypoints use DCS action "On Road" so the AI follows road networks. Speed is gradually reduced toward the destination to allow the column to compress into a tight formation before despawn.

WaypointActionSpeedPurpose
WP 1 — Spawn positionOn Road32 m/s (~115 km/h)Start moving
WP 2 — 100 m aheadOn Road32 m/sFind the road immediately
WP 3+ — Intermediate (route variation)On Road32 m/sShort: 3 direct WPs; Medium: 1 offset; Long: 2 offset
WP n-2 — 200 m from destinationOn Road15 m/s (~54 km/h)Begin slowing — column compresses
WP n-1 — 50 m from destinationOn Road5 m/sSlow crawl — tight formation
WP n — DestinationOn Road3 m/s + ROE Hold FireParking; triggers arrival detection
The destination waypoint sets ROE = Hold Fire (value 4) via a WrappedAction task embedded in the final waypoint, so parked convoys won't shoot at nearby threats.

Arrival Detection

The update loop runs every 5 minutes. For each travelling convoy, it checks the lead unit's position using three progressive checks — any single pass triggers arrival:

Check 1 — Distance / Zone Radius (Primary)

2D distance (x,z only — altitude ignored) from lead unit to destination zone centre ≤ zone radius + 100 m buffer.

Check 2 — Near & Stopped (Secondary)

Distance ≤ 1 500 m AND lead unit velocity < 2 m/s (convoy has stopped).

Check 3 — MIST Zone Verification (Tertiary, if MIST available)

mist.pointInZone() is called with three zone name variants: original name → stripped of _Spawn suffix → full spawnZones mapping lookup.

Stuck Convoy Detection

On each update cycle, the system tracks the lead unit position. If the convoy has not moved more than 20 m within 60 seconds (and the route has not already been retried), the route is re-pushed via controller:resetTask() followed by a simplified 3-waypoint direct route to the destination at 71 m/s. This retry is attempted only once per convoy (convoy.routeRetried = true).

The 5-minute update interval means a stuck convoy may not be detected until the next cycle fires. In the worst case, a convoy can appear stuck for up to ~10 minutes before the retry kicks in.

Warehouse Resupply

On convoy arrival, performWarehouseResupply(destinationZone) is called exactly once (guarded by convoy.resupplied = true).

Resupply Logic

1
Resolve airbase name

Strip _Spawn / _Dest suffix from zone name, look up in ConvoySystem.airbaseNames map → call Airbase.getByName().

2
Get warehouse object

airbase:getWarehouse(). Aborts with a coalition text alert if the warehouse is nil.

3
Top up existing inventory (Option B)

Iterates inventory.weapon and inventory.liquids. Each item with a current count > 0 receives warehouse:addItem(itemName, 20). Fuel items are skipped.

4
Fallback inventory (if warehouse is empty)

If no items were processed, iterates ConvoySystem.fallbackInventory — a table of ~400+ weapon/pod/rocket/bomb/tank/torpedo entries all preset at qty 20.

5
Aircraft increment

incrementWarehouseAircraft() adds +2 to each aircraft type already present in the warehouse.

6
Player notification

Coalition text: "[Airbase] resupplied! +X munitions / +Y aircraft" (displayed for 8 seconds).

Leaderboard Integration

If DGSS_LEADERBOARD is globally available and exposes addConvoyCompletion(playerName, state), the convoy system calls it on every convoy resolution (arrival OR destruction/timeout).

Scoring Formula

survivalRate  = survivingUnits / initialUnitCount × 100
healthRate    = currentTotalHealth / initialTotalHealth × 100
overallScore  = (survivalRate + healthRate) / 2
≥ 85 % → "full"
50–84 % → "partial"
< 50 % → "failed"

Convoys destroyed en-route or timed out (after 5.5 h) are always scored as "failed". The initial unit count and total life pool (unit:getLife0()) are captured at spawn time.

The requester detection scans all active BLUE aircraft/helicopters at the moment the menu command fires. It attributes the convoy to the first player found, not necessarily the player who clicked the menu. In a multi-player environment, ensure coordination so credit goes to the correct pilot.

Mission Editor Checklist

  • Trigger Zones — create 24 zones total: one per base with the exact name (e.g. KANDAHAR) and one spawn zone with _Spawn suffix (e.g. KANDAHAR_Spawn). Recommended radius: 300–800 m for bases, 200–400 m for spawn zones.
  • Airbase Names — confirm each DCS airbase name matches the mapping table exactly (see Zones section above). Rename airbases in ME if needed.
  • Warehouses — enable the Warehouse module in ME (Mission → Options → Mission Features → Warehouse). Pre-stock a small amount of each weapon you want topped up, or the fallback list will be used instead.
  • MIST — load MIST via a DO SCRIPT FILE trigger at mission start (fired once, MISSION START).
  • DGSS_LEADERBOARD — if used, load before this script.
  • This script — load via DO SCRIPT FILE after MIST (delay 2–3 s recommended).
  • Road network — convoys use "On Road" waypoints. Ensure your map has road coverage between zones, otherwise convoys will move cross-country and may get stuck.
  • BLUE country — all convoy templates use country.id.USA. The spawning coalition is coalition.side.BLUE.

Convoy doesn't spawn, coalition message about spawn error Spawn zone (e.g. KANDAHAR_Spawn) doesn't exist in ME or name is misspelled (case-sensitive) Add the trigger zone with the exact name including correct capitalisation and _Spawn suffix.
Convoy travels but warehouse never gets resupplied Airbase name mismatch in ConvoySystem.airbaseNames, or the DCS airbase has no warehouse object Check DCS log for ConvoySystem: FAILED - Could not find airbase. Compare the name in the map against the exact DCS airbase name. Enable warehouses in ME options.
Convoy arrives but arrival is not detected for many minutes Update loop only fires every 5 minutes. Convoy may have arrived mid-cycle. Normal behaviour. Worst case is a 5-minute delay. If persistent, check zone radius in ME — increase to 600+ m.
Convoy stops far from destination and never arrives No road connection between spawn and destination; AI cannot path-find Place intermediate trigger zones on the actual road and consider adding additional waypoints manually. Alternatively the stuck-detection will retry after 60 s with a direct 3-WP route.
