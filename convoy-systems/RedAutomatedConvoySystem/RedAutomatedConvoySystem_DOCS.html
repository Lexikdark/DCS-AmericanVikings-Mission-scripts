RedAutomatedConvoySystem

v5.0 RED Coalition MIST Required Fully automated · Self-perpetuating · On-Road routing · No player input required

Overview

A fully autonomous RED coalition convoy system. On mission start it spawns up to 3 initial convoys, then continuously maintains up to 15 active convoys by spawning a new one every 2 minutes whenever capacity allows. Each convoy is randomly composed from 20 insurgent/militia vehicle templates and travels between randomly selected trigger zones, re-routing to a new destination on arrival — it never despawns naturally; it only terminates if destroyed or stalled.

Key facts  |  Max convoys: 6  |  Initial convoys: 3  |  Spawn stagger: 600 s (10 min)  |  Speed: 22 m/s (~79 km/h)  |  Min route distance: 35 nm (64 820 m)  |  Routing: On Road  |  Update cycle: 30 s

Convoy Zones

Zones are loaded from DCS trigger zones named ConvoyZone1 through ConvoyZone40. The script reads zone.point.x and zone.point.z (stored internally as y in the 2D node table). Missing zones emit a warning and are skipped.

ConvoyZone1ConvoyZone2 ConvoyZone3ConvoyZone4 ConvoyZone5ConvoyZone6 ConvoyZone7ConvoyZone8 ConvoyZone9ConvoyZone10 ConvoyZone11ConvoyZone12 … ConvoyZone39ConvoyZone40
Zone positions are used directly as spawn/waypoint coordinates. Zones should be placed on or near roads so that DCS AI can path-find using the "On Road" waypoint action.

Spawn Flow

1
Manager tick (every 30 s)

Counts active convoys. If below INITIAL_CONVOYS (3), spawns immediately in a burst. If below MAX_CONVOYS (6) and stagger delay (600 s) has elapsed, spawns one convoy.

2
Select start node

Prefers a zone not currently used as any convoy's spawn point. Falls back to any zone if all are occupied.

3
Select destination node

Finds all zones ≥ 35 nm from start, picks one randomly. There is no upper distance cap. If no zone is ≥ 35 nm away, spawning is aborted and an error is logged.

4
Pick random template

Selects one of the 20 ConvoyTemplate globals at random via _G[name].

5
Build unit array (single column)

Units placed in a single-file column at 12 m spacing, all facing the bearing to the destination. Group named ActiveConvoy_ID_TIMESTAMP.

6
Spawn via mist.dynAdd()

Country = CJTF_RED, coalition = "red", category = "vehicle". If dynAdd fails or the group doesn't exist post-spawn, aborts with an error log.

7
Route activation (3 s delay)

After 3 seconds, calls buildRoute() and applyRouteToGroup(). The delay gives DCS time to fully initialise the spawned group before assigning tasks.

8
Register in activeConvoys

Stored with: id, name, group, startNode, endNode, lastPos, lastPosUpdateTime. Stall timer begins implicitly.

Node Selection Logic

SelectionPrimaryFallback
Start node Random from zones not currently used as any convoy's spawn point Random from all zones if every zone is occupied
Destination node Random from zones ≥ 64 820 m (35 nm) from start — no upper distance limit None — if no zone is ≥ 35 nm away, spawn is aborted entirely
Re-route on arrival New destination ≥ 35 nm from current position (old destination becomes new start) Logs a warning if no valid next destination found; convoy idles at destination

Route Building

buildRoute(a, b) generates a 4-waypoint route for every trip. All at altitude 0.

WPActionPositionSpeed
1 — StartOff RoadZone centre (a.x, a.y) — spawns off-road22 m/s
2 — Get on roadOn Road~100 m toward destination — DCS picks up nearest road22 m/s
3 — Leave roadOn Road100 m before destination — travels via road network22 m/s
4 — DestinationOff RoadZone centre (b.x, b.y) — final off-road approach22 m/s
Convoys travel on roads between WP2 and WP3. WP1 and WP4 are Off Road because the spawn and destination zones may be positioned away from the road network. DCS will path-find to the nearest road automatically when the On Road action triggers.
Unlike the BLUE convoy system, there is no speed deceleration approaching the destination. All four waypoints run at the same 22 m/s. The convoy will drive straight through the destination zone and trigger arrival detection on the next update cycle.

The route is applied via controller:setTask({ id = "Mission", params = { route = routeData } }) — not embedded in the spawn data. This means it is applied as a separate task 3 s after spawn.

Vehicle Formation

All vehicles are placed in a single-file column:

  Unit 1  ← heading toward destination
  Unit 2  (12 m behind)
  Unit 3  (24 m behind)
  Unit 4  (36 m behind)
  …

  Spacing: 12 m longitudinal
  Each unit: name = groupName_UN  (e.g. ActiveConvoy_3_1234_U1)

The column is oriented by calculating the bearing from start to destination using math.atan2(dest.y - start.y, dest.x - start.x) and offsetting each unit back along that bearing.

Arrival & Re-routing

Every 10 seconds, updateConvoys() checks the lead unit's position. A convoy is considered arrived when the 2D distance to endNode is less than 75 m.

On arrival, the convoy does not despawn. Instead:

  • The old endNode becomes the new startNode.
  • A new destination is selected (≥ 35 nm away).
  • The stall timer is reset.
  • applyRouteToGroup() is called immediately with the new route.

This creates a self-perpetuating convoy that keeps driving until destroyed or stalled.

Because the update cycle is every 10 seconds and the convoy travels at 22 m/s, it may overshoot the 75 m arrival radius significantly before the check fires. The Off Road final waypoint action gives DCS some flexibility in where the vehicle actually stops.

Stall Detection

On each 10-second cycle, the lead unit's current position is compared to c.lastPos. The logic uses x and z (world coordinates) internally but the lastPos table was originally written with an .y field holding the DCS z-value — they are consistent.

Stall lifecycle
  1. Lead unit moves < 10 m since last cycle → stallDetectedTime is set to now (first occurrence) or compared.
  2. If stalled continuously for > 300 s → group:destroy() is called, convoy is removed from activeConvoys.
  3. If lead unit moves ≥ 10 m → stallDetectedTime is cleared, lastPos is updated to current position.
Once a convoy is destroyed by stall timeout it is simply removed — no re-spawn is triggered immediately. The manager will spawn a replacement on the next tick where active count < MAX_CONVOYS and the stagger delay has elapsed.

AI Behavior

OptionValueEffect
Alarm StateAUTOUnits react to nearby threats; will go to high alert if engaged.
ROEOPEN_FIREConvoys will proactively engage detected BLUE threats — unlike the BLUE system which uses Return Fire only.
Disperse On AttacktrueUnits spread out when taking fire.
RED vs BLUE difference: RED convoys use OPEN_FIRE + AUTO alarm state, making them much more aggressive than BLUE convoys (which use RETURN_FIRE + GREEN). RED convoys will stop and engage if they detect a target, which can trigger the stall detector if combat lasts > 5 minutes.

Update Loop

A single self-rescheduling timer drives the entire system:

convoyLoop()  ← called every 30 seconds
  ├─ updateConvoys()   -- checks each active convoy:
  │    ├─ Group dead?        → remove from activeConvoys
  │    ├─ Lead unit gone?    → remove from activeConvoys
  │    ├─ Stall check        → destroy if stalled > 5 min
  │    └─ Arrival check      → re-route if within 75 m
  └─ convoyManager()   -- capacity management:
       ├─ Count active convoys
       ├─ Burst-spawn if count < INITIAL_CONVOYS (3)
       └─ Spawn 1 if count < MAX_CONVOYS (6) and stagger delay elapsed (600 s)

The loop uses return timer.getTime() + 30 to self-reschedule. All convoy management (stall, arrival, spawn) occurs within this single 30-second tick.

Mission Editor Checklist

  • Trigger Zones — create 40 zones named exactly ConvoyZone1 through ConvoyZone40 (case-sensitive). Fewer zones work but reduce route variety.
  • Zone placement — place zones on or very close to road junctions/intersections. The very first waypoint is Off Road (zone centre); WP2 is the first On Road point 100 m ahead. If there is no road within DCS pathing range of the zone, the convoy will drive cross-country.
  • Zone spacing — at least some zones should be > 35 nm apart. If all zones are within 35 nm of each other, every convoy uses the "farthest zone" fallback and logs a warning every spawn.
  • MIST — load before this script, no exceptions.
  • Country — convoys spawn as country.id.CJTF_RED. This must be enabled for the mission coalition.
  • No ME groups needed — all groups are spawned dynamically. No RED ground groups need to be pre-placed in the mission.

Troubleshooting

SymptomLikely CauseFix
No convoys spawn, log shows "No convoy nodes loaded" No trigger zones named ConvoyZone1–ConvoyZone40 found in ME Add the zones with exact names. Even 1 zone will allow the system to start (but spawning logic needs at least 2 zones).
Convoys spawn but immediately stop and are cleaned up after 5 min Zones placed off-road in terrain AI cannot navigate; convoy immediately stalls Move ConvoyZone trigger zones to road junctions. The Off Road → On Road WP transition requires a road within ~100 m.
All convoys log "Could not find ANY destination", no convoys spawn All zones are within 35 nm of each other — no destination qualifies Spread zones further across the map, or reduce MIN_TRAVEL_DISTANCE in the config section.
Convoy spawns but drives in the wrong direction Normal — unit positions are offset away from destination so they drive toward it No fix needed. If persistent misdirection: verify DCS road network connectivity between zone pairs.
Active convoy count never reaches 6 Convoys are being destroyed (by players or stall timeout) faster than the 10-minute stagger allows respawning Reduce STAGGER_DELAY or increase MAX_CONVOYS in the config.
dynAdd fails (log: "dynAdd failed for convoy") MIST not loaded, or unit type string is misspelled in a template Verify MIST is loaded first. Check each DCS unit type string in the templates against the DCS unit database.
Convoys stop engaging and sit idle (triggering stall) ROE = OPEN_FIRE means convoys will stop to fight; if combat exceeds 5 minutes the stall timer kills them Increase STALL_TIMEOUT (e.g. to 600 s) if convoys should survive extended engagements.
