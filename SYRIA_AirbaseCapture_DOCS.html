SYRIA AirbaseCapture

SYRIA_AirbaseCapture.lua  ·  Dynamic ownership & F10 map drawing  ·  Syria map  ·  Requires MIST 4.5

How It Works

Three things happen, in this order:

  1. Script loads — reads the hard-coded ABC.REGISTRY list, looks up every airbase position via Airbase.getByName(), and draws a coloured circle on the F10 map for each one.
  2. Every 180 seconds — counts ground units of each coalition inside each base's trigger zone. If one side has units there and the other doesn't, a capture tick increments. After 3 ticks it flips.
  3. On flip — recolours the circle, announces to all players, fires the optional ABC.onCapture callback.
You provide: Trigger zones in the ME (one per base, named exactly as in the registry). The script provides: everything else — circles, scanning, state tracking, announcements.

Configuration — Timing

Click any row to expand the full explanation.

CHECK_INTERVAL 180 s How often the script scans all zones for units. ▼ details

Every CHECK_INTERVAL seconds the main scanAll() loop fires and checks every registered base. It counts ground units of each coalition inside the trigger zone, increments capture ticks if appropriate, and redraws labels if anything changed.

Practical effect: This is the "heartbeat" of the entire system. Lowering it makes the game feel more real-time (units react quickly), raising it makes captures slower and less sensitive to brief incursions. At 180 s with 3 ticks, the minimum capture time is 9 minutes of uncontested presence.

Tuning guide:
• Fast / arcade: 30 s → min capture 1.5 min
• Balanced: 60 s → min capture 3 min
• Slow / milsim: 180 s → min capture 9 min (current)
• Very slow: 300 s → min capture 15 min

CAPTURE_TICKS 3 How many consecutive successful scans are needed to flip a base. ▼ details

A "tick" is one successful scan where the capturing side has units present and the defending side has none. CAPTURE_TICKS defines how many of those in a row are needed before ownership actually changes.

Why it exists: Without this, a single scout vehicle driving through would flip a base. The tick system requires sustained, uncontested occupation.

Ticks reset to 0 if the defending side returns before the threshold is reached. A partially-captured base (e.g. 2 of 3 ticks done) goes back to 0 if contested.

The F10 label shows a "Capturing... X%" progress during the tick accumulation so players can see it happening in real time.

Minimum capture time = CHECK_INTERVAL × CAPTURE_TICKS. At defaults: 180 × 3 = 540 s = 9 min.

MIN_CAPTURE_UNITS 1 Minimum friendly ground units needed inside the zone to start a tick. ▼ details

The capturing side must have at least this many live ground units inside the trigger zone when the scan fires. If their count is below the threshold, no tick is awarded even if the enemy is absent.

Default of 1 means a single infantry unit is enough to contest a base. Raise to 3 or 5 to require a meaningful force rather than a lone scout.

Note: This threshold applies independently to each side. If RED has 5 and BLUE has 0, RED accumulates. If BLUE has 1 and RED has 5, the base is contested — neither ticks up.

Configuration — Scanning

SCAN_AIR false Whether aircraft and helicopters count toward zone presence. ▼ details

When false (default), only ground units (Group.Category.GROUND) are counted. This is the realistic default — a jet flying over a base doesn't "occupy" it.

When true, the script also counts AIRPLANE and HELICOPTER categories. This means a helicopter hovering over a zone contributes to capture ticks. Useful for FARP capture scenarios where heliborne assault is the primary mechanic.

Performance note: Setting this to true roughly doubles the unit iteration cost per scan since all air units in both coalitions are also checked. On large missions this is negligible; on missions with hundreds of aircraft it adds a small overhead every CHECK_INTERVAL seconds.

Configuration — Map Drawing

CIRCLE_RADIUS 6500 m Radius of the F10 map circle drawn around each base. Does NOT affect the capture zone. ▼ details

This is purely cosmetic — it controls how large the coloured circle looks on the F10 map. It has no effect on what counts as "inside the zone" for unit scanning. Zone size for capture is determined by the trigger zone radius you set in the Mission Editor.

The text label is offset from the centre by roughly half this value so it sits just inside the circle edge. If you change this value significantly, the label position adjusts automatically.

Recommended values:
• Major international airport: 8000–10000 m
• Military airbase: 5000–7000 m (current default 6500 m)
• FARP / small strip: 2000–4000 m

COLOR_RED / FILL_RED (etc.) {r,g,b,a} RGBA colour values for each state's circle outline and fill. ▼ details

Each state has two colour entries: COLOR_* for the circle outline/border and FILL_* for the transparent interior fill. Both use DCS's {r, g, b, a} format where all values are between 0 and 1.

The a (alpha) value controls opacity. Outline colours use a=0.90–0.95 for a strong visible edge. Fill colours use a=0.08–0.13 to keep the interior faintly tinted without obscuring the map underneath.

All four state pairs are: COLOR_RED, FILL_RED, COLOR_BLUE, FILL_BLUE, COLOR_NEUTRAL, FILL_NEUTRAL, COLOR_DESTROYED, FILL_DESTROYED.

LINE_TYPE 1 (Solid) Border line style: 1=Solid, 2=Dashed, 3=Dotted, 4=Dot-Dash. ▼ details

DCS supports four line types for circleToAll. The default solid line (1) gives the clearest visibility. Dashed (2) or dotted (3) can help if you have many overlapping zones and want to distinguish them.

LABEL_FONT_SIZE 14 Point size of the base name + status text on the F10 map. ▼ details

Controls the size of the text label drawn next to each circle. The label shows the base name on line 1 and the ownership status on line 2 (e.g. [ RED ]). During active capture it adds a third line showing percentage progress.

DCS renders F10 map text at fixed pixel sizes regardless of zoom level, so larger values are easier to read when zoomed out at the strategic level. Reduce to 10–11 if labels feel cluttered.

Configuration — Mark IDs

BASE_MARK_OFFSET 6000 Starting integer ID for all F10 map marks placed by this script. ▼ details

DCS F10 map marks are identified by integer IDs. This script allocates a block of MARKS_PER_BASE (4) IDs per base, starting from BASE_MARK_OFFSET.

So with the default 6000 offset and ~35 bases in the registry:
• Base 1 uses IDs 6004, 6005, 6006, 6007
• Base 2 uses IDs 6008, 6009, 6010, 6011
• Base 35 uses IDs 6144–6147

Conflict risk: If another script in your mission uses trigger.action.markToAll / circleToAll with IDs in this range, marks will collide (one script deletes the other's marks). Change BASE_MARK_OFFSET to a safely different range, e.g. 10000.

IDs 0 and 1 within each block are used; 2 and 3 are reserved for future expansion.

MARKS_PER_BASE 4 How many mark IDs are reserved per base (circle + label + 2 spare). ▼ details

Currently only 2 marks are used per base (circle at offset 0, text label at offset 1) but 4 are reserved to allow future additions without changing the ID layout. Do not reduce this below 2.

Function — ABC.getOwner()

ABC.getOwner(baseName)→ "RED" | "BLUE" | "NEUTRAL" | "DESTROYED" | nil
Ask the script who currently owns a base.
▼ details

What it does: Looks up the internal state table for the given base name and returns its current coalition string. Returns nil if the name is not in the registry.

When to use it: From any other script that needs to gate logic on airbase ownership. For example, only spawn a logistics convoy if a friendly base is upstream, or trigger a mission objective complete when BLUE captures all three northern bases.

-- Example: check before spawning a convoy
if ABC.getOwner("Aleppo") == "BLUE" then
  GROUP_Convoy:activate()
end

-- Example: count how many bases RED holds
local redCount = 0
for _, name in ipairs({"Mezzeh","Hama","Tiyas","Tabqa"}) do
  if ABC.getOwner(name) == "RED" then redCount = redCount + 1 end
end

Note: The name must match exactly (case-sensitive) as written in ABC.REGISTRY. Use the name field, not the zone name.

Function — ABC.forceCoalition()

ABC.forceCoalition(baseName, coalStr)
Instantly set a base to any coalition, bypassing capture ticks.
▼ details

What it does: Skips the tick accumulation system entirely and immediately sets ownership to the given coalition string ("RED", "BLUE", or "NEUTRAL"). Redraws the F10 circle, announces the change to all players, and fires ABC.onCapture if set.

When to use it:

  • Mission start setup — pre-position frontlines without waiting for the tick loop.
  • Scripted narrative events — e.g. a timed trigger flips an airbase as part of a campaign story beat.
  • Player reward — complete a bombing objective and then call forceCoalition to hand the base to BLUE immediately.
  • Admin / testing — reset a base mid-mission without restarting.
-- Instantly give Hama to BLUE (scripted assault complete)
ABC.forceCoalition("Hama", "BLUE")

-- Reset Palmyra to neutral at a certain mission time
ABC.forceCoalition("Palmyra", "NEUTRAL")

Important: This does NOT sync the DCS engine's internal airbase coalition (which affects ATC callsigns and parking). To sync that, you need to enable auto-capture in the ME airbase properties, which will fire S_EVENT_BASE_CAPTURED and the script will catch and sync it in the other direction.

Function — ABC.setDestroyed()

ABC.setDestroyed(baseName)
Mark a base as destroyed and remove it from the capture system permanently.
▼ details

What it does: Sets the base state to "DESTROYED", which is a terminal state. The scan loop skips destroyed bases entirely. The F10 circle recolours to dark grey. A "[AIRBASE DESTROYED] X is no longer operational" message is sent to all players.

DESTROYED is final for the mission. There is no ABC.setRestored() function. The only way to bring a base back is to call ABC.forceCoalition() with a valid coalition, which will override the destroyed state.

When to use it:

  • A runway-busting strike completes — gate it on a trigger condition or DCS unit-dead event.
  • A SCUD or ballistic missile hits a base — trigger it from a weapon impact event.
  • Decommissioning a base as a mission objective is completed.
-- Example: Inside a DO SCRIPT trigger when all runway objects are dead
ABC.setDestroyed("Tiyas")    -- T-4 is now unusable

Function — ABC.registerFARP()

ABC.registerFARP(farpName, zoneName, startCoal, pos)
Add a FARP to the capture system at runtime with a specific world position.
▼ details

What it does: FARPs are not DCS airbase objects with known positions, so they can't be auto-populated in the registry at load time. This function adds a FARP as a new entry mid-mission, allocates it a mark ID block, draws it on the F10 map immediately, and starts including it in the scan loop.

Parameters:

ParamTypeDescription
farpNamestringUnique name used as the key everywhere (must match the DCS FARP unit name if you want Airbase.getByName() to work)
zoneNamestringExact name of a trigger zone you placed in the ME
startCoalstring"RED", "BLUE", or "NEUTRAL"
posVec3DCS world coordinates {x, y, z} — get from Airbase.getByName("FARP_x"):getPoint() or a static object
-- Triggered 5 s after mission start to ensure FARP objects exist
ABC.registerFARP(
  "FARP_Khanasir",
  "ZONE_FARP_Khanasir",
  "RED",
  Airbase.getByName("FARP_Khanasir"):getPoint()
)

Safe to call repeatedly: Calling it for a name that's already registered logs a warning and returns without duplicating it.

All FARPs are capturable = true by default. There is no way to register a locked FARP through this API; add it directly to the registry table as a static entry with capturable = false if needed.

Function — ABC.redrawAll()

ABC.redrawAll()
Delete and redraw every F10 map circle from scratch.
▼ details

What it does: Iterates every entry in the registry, calls clearMarks() (removes old DCS marks), then calls drawBase() to replace them with fresh marks in the current coalition colour.

When to use it:

  • After a batch of forceCoalition calls — instead of N redraws, call one redrawAll at the end.
  • If you suspect marks have been accidentally deleted (e.g. another script with conflicting mark IDs).
  • On a scripted "brief" trigger where you want to force all circles to refresh for a new player who just connected.

Cost: Calls removeMark + circleToAll + textToAll for every registered base in a single frame. On a typical Syria setup with ~35 bases this is ~70 DCS API calls — completely fine as a one-off call, but do not call it in a tight loop.

Callback — ABC.onCapture

ABC.onCapture = function(baseName, prevCoal, newCoal) ... end
Optional hook called every time any base changes ownership.
▼ details

What it does: If you assign a function to ABC.onCapture, the script calls it via pcall (so a crash in your callback won't bring down the capture loop) every time ownership changes — whether via normal capture ticks, forceCoalition, or setDestroyed.

Callback signature:

ParameterTypeValue
baseNamestringName of the base that changed
prevCoalstringPrevious coalition: "RED", "BLUE", "NEUTRAL"
newCoalstringNew coalition after the change
ABC.onCapture = function(base, from, to)
  -- Award score
  if to == "BLUE" then missionScore = missionScore + 100 end

  -- Trigger IADS node rebuild immediately
  if type(buildNodeList) == "function" then
    buildNodeList(coalition.side.RED)
    buildNodeList(coalition.side.BLUE)
  end

  -- Announce on radio for specific asset
  if base == "Mezzeh" and to == "BLUE" then
    trigger.action.outTextForCoalition(coalition.side.BLUE,
      "Mezzeh secured. ATC online.", 15)
  end
end

Only one callback at a time. Setting ABC.onCapture again overwrites the previous value. Wrap multiple actions in a single function.

When to set it: In a DO SCRIPT trigger at T+1 s (after both MIST and AirbaseCapture have fully loaded), not in the same trigger as the DO SCRIPT FILE actions.

Mission Editor Setup Checklist

  1. Load scripts — MISSION START trigger → DO SCRIPT FILE: mist_4_5_126.lua then SYRIA_AirbaseCapture.lua
  2. Place trigger zones — one per capturable base, named exactly as the zone field in the registry (e.g. ZONE_Tiyas). Locked bases still need zones if you want unit counting (even though they won't flip). You may omit zones for locked bases if you just want the F10 circle with no logic.
  3. Zone radius — set in the ME trigger zone properties. Recommended 6–10 km for airbases. This is independent of CIRCLE_RADIUS in the config.
  4. FARPs — add a delayed DO SCRIPT trigger (T+5 s) calling ABC.registerFARP(...) for each one.
  5. Callback — if using ABC.onCapture, set it in a DO SCRIPT trigger at T+1 s (not in the same trigger as the DO SCRIPT FILE).
Quick test: load the mission and open the F10 map. If the script loaded correctly you will see coloured circles over all registered airbases within the first few seconds, before any units have moved.
